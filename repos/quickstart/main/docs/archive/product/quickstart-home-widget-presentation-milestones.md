# 首页模块形态与显示设置：M66.26～M66.31

2026-10-16。用户认可“业务模块＋展示形态＋显示属性＋槽位适配”，要求形成产品及架构文档与可测试的实施计划。编号检索确认现有阶段止于M66.25，新增M66.26～M66.31，无重复。

依据：[唯一产品规范1.2](quickstart-home-layout-interaction-spec.md)R17～R24、WP01～WP16；[架构设计参考](quickstart-home-widget-presentation-architecture.md)。用户授权连续执行后，M66.26～30技术检查通过，M66.31技术交付及用户人工验收通过，见[执行状态](../evidence/m66/widget-presentation/status.md)。下文保留任务树及验收定义；实现基线`952528c`，本轮按用户要求提交原型代码，未开展正式业务开发。

## 共同范围与执行规则

- 六阶段先完成隔离Vue原型，复用现有Vue／CSS、模块身份及业务语义，使用5180、合成数据、内存草稿。用户确认后再单独计划正式首页、真实API／持久化、安装打包及实机验收。
- 不修改系统左侧菜单或原NetworkFlow主视觉；保持有序行、唯一模块、同排等高、模块迁移替换、整行拖动排序及原有恢复规则。新形态不代表放开任意嵌套。
- 已确认的上限是6个常用项；“双行／三行”是目标排布，非必须填满的空行。新增形态和尺寸必须有真实内容，不以CSS缩放／裁切通过。
- 开始每阶段先输出任务树、可测试目标、当前候选与证据位置；实现后自检。初检失败最多优化3次，逐轮保留失败报告、截图、原因和修订；仍失败或需要重要产品语义决定时停止说明。该执行规则在后续实施时适用，本次规划核对不消耗实施优化次数。
- 每条验收记录包含前置文档／偏好、容器和目标、真实操作、预览、草稿／已应用／历史、撤销结果及源码／资源标识。纯逻辑测试与真实输入测试分工，不能用内部函数调用代替用户输入验收。
- 阶段完成不能仅凭编译、HTTP200、提示文案或历史截图。新的候选修改已验收契约时，复验受影响阶段；自动化、设计者审图及人工体验分别记录。
- 上一阶段必要输出是下一阶段输入，达到目标后可继续下一阶段；最终人工体验仍需用户参与，不能自行宣布通过。执行授权以用户后续明确指令为准。

## M66.26 统一模块契约与版本化草稿

**目标：** 模块定义、选择器、尺寸计算和渲染有唯一依据，为后续真实Vue内容提供同一份解析与变更计划。

任务树：

1. 盘点十个模块及五模板角色 → 保留真实现有形态 → 区分待设计形态与已允许位置。
2. 建立有限形态、类型化属性、默认值、最低／建议尺寸、容量／溢出和响应式定义。
3. 建立版本化`{rows, widgetPreferences}`、schema迁移与完整快照 → 兼容旧rows。
4. 建立无副作用的形态解析与变更计划 → 三类结果、原因、baseRevision及候选结果 → 契约用例。

可测试验收：

1. **WP01：** 十模块均有真实现状登记，五模板的普通槽、大侧、小槽逐项有支持／拒绝理由。未设计设备上下摘要不能因新增compact名称自动开放；原图形态不缩小重做。
2. 同一输入解析结果稳定；各开放形态与属性有最低尺寸边界、边界以下、建议高度及溢出结果。应用2／3行计算可用逻辑样例先验证，真实像素待M66.27校准，不能将候选值写成实测。
3. **WP02：** 旧rows迁移后模块唯一、顺序、比例、高度保持，补默认偏好；未知schema／非法属性／未知ID可诊断并保留原数据。原型不请求或写真实偏好接口。
4. 三类结果均有明确样例：无需修改可放入、需提高行高／明确换形态、没有合法位置。解析不修改输入、不发请求、不写历史；过期revision不能执行旧计划。
5. 适配规则不再散落成互相矛盾的常量；旧消费者可兼容迁移，但新形态必须消费新契约。R17～R24和WP场景均有责任阶段，无遗漏规则。

证据：`docs/archive/evidence/m66/widget-presentation/26-contract/`，模块登记、契约与迁移报告、规则映射、候选尺寸标注及失败轮次。

## M66.27 应用与工具形态及显示设置

**目标：** 用户能选择启动条／图标网格，直观看到双行、三行排布及所需高度；半宽应用是自然的真实卡片。

任务树：

1. 将应用真实Vue内容接入统一定义 → 启动条／网格内容与入口设计 → 容器尺寸实测。
2. 自动／单行／双行／三行属性 → 目标列数、实际行数、容量及剩余项入口。
3. 模块“显示设置”面板 → 子草稿与真实预览 → 采用／取消、焦点与互斥。
4. 以同排测试夹具验证应用＋设备的共同高度 → 长名称、应用缺失与全部入口审图。

可测试验收：

1. **WP03：** 6项且空间足够时双行为3列×2行、三行为2列×3行；启动条与网格内容真实可见，无重叠或CSS裁切。与设备同排外框对齐误差≤1 CSS px。此阶段可用确定布局样例验证，不声称槽位协商已接入。
2. **WP04：** 0／1／4／6项、长中文／英文名、窄卡容量不足、应用清单加载／空／失败均检查实际呈现；4项三行偏好允许均衡2×2并标明实际结果。不复制图标或改变常用项顺序，更多数量准确、全部／工具／软件中心可操作。
3. **WP06：** 仅编辑时出现模块显示设置入口；设置预览不改首页草稿、已应用或历史，采用一次提交，取消精确还原、焦点回到打开者。行高仍由行布局管理，不出现第二份独立行高输入。
4. **WP09：** 记录真实标题、内边距、图标区、名称两行及间距，校准最低／建议高度；行高足够不变、不足显示增高影响，确认后属性和行高一并提交。减少图标行数不自动缩行，应用清单刷新不增高。
5. 320／390／768／1440px和两主题覆盖代表状态，保存实际容器尺寸和截图；设计者审阅图标大小、名称、留白及邻卡等高，不能只检查元素是否存在。

证据：`docs/archive/evidence/m66/widget-presentation/27-applications/`，真实规格尺寸表、排布／容量矩阵、设置子草稿与撤销、入口操作和视觉记录。

## M66.28 设备形态与共享业务语义

**目标：** 设备标准列表与摘要统计是同一业务模块的不同呈现，验证统一架构能支撑内容实质不同的两种模块。

任务树：

1. 设备标准／摘要的信息层级及内容上限 → 统一库存投影与状态解释。
2. 形态接入同一设置入口 → 自动／指定偏好与当前实际呈现说明。
3. 两形态的查看全部／单设备路径 → 无DHCP权限、缺限速引擎与API状态。
4. 十模块定义复核 → 现有标准／上下摘要接入契约 → 不开放尚无真实内容的新形态。

可测试验收：

1. **WP05：** 标准形态展示有界列表和统计，摘要形态聚焦统计及必要状态；名称、deviceId、在线／发现含义与库存投影逐项一致。首轮标准列表上限沿用最多6项并按空间有界减少；摘要不虚构列表或数据，具体空间阈值记录实测。
2. 查看全部进入完整列表，标准列表中的单设备进入相同deviceId目标；筛选范围与状态解释沿用现有契约。两形态不各自拼一套设备识别、权限判断或请求。
3. 加载、无设备、API失败、旧版、权限失败、缺少／停止／异常限速服务均有局部呈现；缺引擎仍能展示库存。没有DHCP分配权的文案准确，不因切形态将只读变可编辑。
4. **WP10：** 自动与指定形态分别做宽→窄→宽三次，显示偏好不变；指定形态需要改变时明示，不自动覆盖。普通槽／上下大侧／上下小槽分别校验，手机拆行不能绕过逻辑不支持。
5. 应用启动条／网格、设备标准／摘要均由统一定义解析与渲染。其余八模块有真实现有形态登记和回归入口；未设计的新形态继续禁用，不以全量三档表格冒充内容完成。

证据：`docs/archive/evidence/m66/widget-presentation/28-devices/`，信息与状态矩阵、身份／权限／导航报告、偏好往返和实际截图。

## M66.29 适配协商与完整事务

**目标：** 用户能把设备放入原先过矮的应用行，选择合理方案后一次完成；所有输入、预览和恢复使用同一份计划。

任务树：

1. 槽位选择器三类结果 → 可调整项保持可选 → 显示少量明确方案及影响。
2. 点击／键盘／鼠标拖放／触摸 → 同一计划 → 需要额外调整时单次确认。
3. 所有布局命令接入计划 → 完整文档快照 → 撤销、取消、隐藏与空位整理。
4. 活动动作互斥 → 草稿／目标版本检查 → 中断取消与焦点恢复。

可测试验收：

1. **WP07：** 用真实点击完成“176px应用行改双列、选择设备、提高共同高度后放入”，无需先关闭选择器手动调高。三个结果分支均断言原因与实际布局；来源留空、目标替换、被替换项隐藏，全页唯一。
2. **WP08：** 相同起始文档，鼠标、触摸、纯点击、键盘得到相同候选及提交快照。无需额外调整的移动保持已验收方式；需调整的拖放松手后等待确认，悬停／待确认／取消均不写草稿或历史，不自动扩列或挪走第三模块。
3. **WP09／WP11：** 共同高度遵守普通并排最大值及上下分割约束；移入、替换、形态／属性和必要高度一次提交，一次撤销还原完整文档。隐藏再添加保留偏好，缩槽与整理空位不丢设置；不改变原有保留项确认和不跨行补洞规则。
4. **WP11：** 完成、重新编辑、整份取消、恢复推荐、形态切换后的撤销均覆盖rows及widgetPreferences；历史≤30，不修改独立常用项清单或已应用业务策略。
5. **WP12：** 待确认时修改草稿或使目标失效，旧计划拒绝且保留当前文档；Escape、pointercancel、失焦、resize、切换视图／面板及卸载清理。没有半个手势提交、重复确认或监听残留，取消后焦点正确恢复。

证据：`docs/archive/evidence/m66/widget-presentation/29-negotiation/`，三分支与真实输入报告、计划前后快照、过期负例、原子撤销和中断清理。

## M66.30 当前候选完整回归与资源验证

**目标：** 新形态不破坏已验收布局交互，当前真实浏览器候选在窄屏、异常状态及连续操作下保持清楚、稳定和有界。

任务树：

1. 类型及契约检查 → WP01～WP14整合 → 受影响SC与整行RS回归。
2. 普通态／编辑／总览／设置／适配确认 → 视口、语言、主题及临界尺寸矩阵。
3. 长名称与业务状态 → 实际截图审图 → 键盘、触摸及减少动态效果。
4. 20次切换／采用／撤销 → 跨采样周期观察 → 隐藏、卸载及边界检查。

可测试验收：

1. 当前源码TypeScript、WP01～WP14及受影响SC01～SC23、RS01～RS08通过；浏览器控制台及请求无新增错误，无真实路由器写入或设计预览意外访问真实设备。
2. **WP13：** 320／390／768／1024／1440／1920px × 两主题 × 中／英文共24组普通态基准；320、768、1440px补编辑／总览／设置／适配确认代表组合。无非预期横向溢出、遮挡或菜单侵占，主要触摸目标≥44×44 CSS px、同排对齐误差≤1px。每种新形态保存阈值上下的实际容器尺寸。
3. 自动与指定形态、五模板宽窄往返、0／1／4／6项、长名称、应用与设备的加载／空／失败／旧版／无权限及可选服务缺失有实际覆盖。普通首页不因状态变化重排或变高。
4. 核心任务有真实鼠标、点击、键盘及触摸事件；焦点循环／恢复、Escape、减少动态效果可用。手机无需依赖拖动完成设置与适配确认，说明模拟触摸与物理设备的区别，不冒充完整读屏认证。
5. **WP14：** 20次形态／属性／总览切换及采用／撤销后，10600ms观察原图单一5秒采样2～3次，其他读取按既有30／60秒周期无倍增；隐藏／卸载后5600ms新增应停读取0次，日志≤120、历史≤30，无活动手势帧或监听残留。不能用短于5秒的快循环证明没有泄漏。
6. 保存正常视口与同宽完整内容截图，实际查看原图、设置预览、更多入口及留白；不能只检查HTTP200、DOM可见或活canvas。发现问题保留对应候选与失败图，修改后重验受影响项。

证据：`docs/archive/evidence/m66/widget-presentation/30-review/`，当前回归、24组基准、编辑代表态、阈值／状态／输入、资源报告及设计审图。

## M66.31 交付评审与正式开发交接

**目标：** 提供用户能访问并复验的当前5180候选，完成人工体验确认，并把可复用契约、差异和真实业务进入条件交接清楚。

任务树：

1. 公共预览所有权／资源与受测源码核对 → 规则、场景、证据矩阵回填。
2. 人工独立任务卡 → 操作记录与主观反馈 → 新形态体验确认。
3. 产品规范／架构／操作指南同步 → 原型与真实业务代码映射 → 正式存储、接口及验收留项。
4. 分类交付：已实现／当前已验证／未验证／待正式产品决定 → 冻结当前候选。

可测试验收：

1. **WP15：** 当前5180可访问、绑定0.0.0.0且属于本项目；公开全部JS/CSS逐项哈希匹配受测构建，记录源码指纹、候选版本／提交及dirty状态。部署／刷新后的当前候选复验，不用旧截图和旧PID替代。
2. R01～R24、SC／RS与WP01～WP16有对应实现、证据或明确未验证说明，已通过结果绑定实际候选；设计认可、技术通过和人工确认不混写。
3. **WP16人工任务：** 前置为当前候选、正常合成数据及在布局编辑外准备好6个常用项；记录进入时的布局与偏好。用户独立完成①6项应用改双行并与设备同排；②改三行并确认必要高度；③选择设备摘要再恢复指定形态；④将设备移入短行并确认／取消适配；⑤撤销及取消编辑恢复原文档；⑥总览整行排序后返回真实页面。记录是否需提示、误操作／撤销次数和反馈，未经参与不判通过。
4. 用户明确确认新形态与属性的功能／体验后才完成本阶段；技术通过但未参与时记“已交付、待人工评审”，不反复自动请求或自行标通过。涉及重要语义改动先修订规范再实施。
5. 正式开发交接包含：统一定义／解析／计划接口、版本化文档与迁移样例、数据订阅所有权、已有请求层／库存适配位置、原型合成数据替换点、当前可复用测试及真实环境新增测试要求。
6. 明确列出尚需后续决定的偏好作用域、多用户共享、真实存储／ACL／并发版本、损坏恢复及前后端schema兼容，不假定账号同步或臆造接口。正式业务、安装包、设备验收和24小时观察保持独立状态，不以原型通过代替。
