# 主路由后端更新

用户明确要求更新 `.1` 最新后端，授权完成该后端替换及 Quickstart 服务重启。仍保护主路由网络/DHCP/防火墙、其他服务和既有数据；不执行网络策略、安装钩子、DHNS启动、故障切换或系统重启。

目标：使当前正式前端可读取并保存路由器共享首页设置，消除因旧后端缺接口导致的两条错误提示。

任务树与验收：

1. 重新检查实际架构、后端/PID、启动脚本、配置、前端指纹和保存文件。当前 x86_64 / runtime0.14.0；服务仅执行 `quickstart serve --unix ...`，disable_dhns未设置且无startdhns/独立DHNS命名空间。启动源码仅初始化DHNS连接服务，不启动DHNS网络设置。
2. 当前 `backend` 源码与冻结 `c9624a3` 完全相同，复用匹配0.16.6 x86_64产物；重新运行本地测试、核对归档及ELF、保留旧程序和配置私有备份。无需重建相同后端或替换当前新版前端。
3. 原子替换主程序，仅重启 Quickstart；核验运行进程的实际exe/hash/命令和版本。失败恢复旧程序，不修改网络来绕过验证。
4. 首次认证GET按既有迁移规则生成首页配置，不覆盖旧UCI；登记八条首页配置keep路径，使旧包环境的系统备份覆盖新配置。
5. 用真实root短期会话验证两个域读取、无变化保存及重复读取的版本/文件稳定；设备列表/角色/DHCP仍可用；首页无配置提示、布局编辑及应用工具可用，取消编辑不保存。桌面和手机截图实际打开审查。
6. 比较网络配置、netifd/dnsmasq/uhttpd等进程、LAN/默认路由、前端资源和包数据库前后不变；销毁临时会话，归档。最多三轮优化，保留失败证据。

不计作完整IPK安装，opkg元数据保持原版；不更新B/C/D、5180，不推送或发布。
