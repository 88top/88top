## 上一轮试设计：A 紧凑概览与应用（历史）

2026-10-15 用户指出网络区被右侧连接/配置卡片撑高，应用能力又分散为软件中心、配置工具、快捷操作。本轮 A 使用“紧凑概览＋应用”：原曲线组件保留，图表独立高度；应用与系统工具聚合在网络区下方的单个操作区。下文上一轮“模块内入口”规则保留历史，不作为新布局位置依据。

任务树：解除图表与右栏高度耦合 → 合并应用/工具操作区 → 常用应用选择与全部清单 → 无应用/失败/加载/大量应用降级 → 当前多端、导航、采样、宿主边界自检。验收：桌面图表288～352px、手机288px；系统工具页签、网络详情或模块显隐均不改变图表本身高度；软件中心为安装/更新唯一入口；默认四个常用入口，最多六个；选择、排序、取消与应用可操作；应用读取失败不妨碍系统工具和内置功能；默认桌面/平板首屏包含应用区并开始呈现设备，手机单列滚动；无横向溢出或覆盖系统菜单；八工具、原五入口、设备身份与权限可达。最多优化3次，证据另存 `docs/archive/evidence/m66/compact-applications/`。

### 能力与位置

| 能力 | 职责 | 首页呈现 |
|---|---|---|
| 软件中心 | 查找、安装、更新、卸载软件 | 应用区标题栏单个“软件中心”入口，不作为普通应用卡片重复展示 |
| 已安装应用 | 打开已有软件 | “全部应用”清单，可选择到常用区域；不把安装状态等同于运行状态 |
| 系统工具 | 本机维护与配置 | 与常用入口共享同一块区域，以页签切换八个工具；不再挤在图表右侧 |
| 内置功能 | 设备、文件、网络等 Quickstart 自带功能 | 按任务放在内容模块中，也可选择为常用入口；不伪装为已安装软件 |
| 服务详情模块 | 运行状态、用量、目录等观察信息 | 可单独开启，不与启动应用卡片混为同一功能 |

默认常用：文件管理、Docker、qBittorrent、DDNSTO，仅显示图标、名称及一行用途，不重复完整服务状态。Docker、下载、远程详情卡默认收起，可在自定义首页中开启；设备、系统、磁盘、共享摘要保留。原图下方先给一行清晰操作，再进入设备和资源信息。

桌面图表采用 `clamp(288px,34vh,352px)`，手机288px。图表不跟随右侧高度拉伸，网络详情展开可增加详情所在行高度，但图表自身不变。中等宽度保留紧凑连接卡；手机上下排列。缩短页头，取消重复英文大标题，保留原青色/紫色面积曲线和采样。

常用入口编辑最多6项，支持选择顺序和上下移动；取消恢复，应用在本页内存中保存，导航返回保留，刷新恢复预设。隐藏设备/网络模块时，入口收纳到应用区快捷操作；收起应用区则保留一个“应用与工具”按钮，打开完整面板。页签切换后不把重复网格同时铺开。

### 数据与架构约束

应用原型数据全部为合成目录，明确不是设备安装证据；未新增自动安装、启动、停止或扫描任务。正式设计可复用现有 `/app/install-list/` 的名称/标题/entry 等元数据，以及已有 LuCI `/store/installed/` 来源，先验证适用版本与返回约定；最终只能选一个权威安装目录来源，不能同时轮询拼成两套安装状态。应用身份用包/应用 ID，首页收藏用稳定 ID，不以显示名称或 URL 为键；系统工具/内置功能由固定注册表提供，与安装列表分开。

现有 Go `/app/install-list/` 适配层把读取错误映射为空列表，正式实施前须解决“读取失败”和“确实没有应用”的区别；本原型独立演示这两种状态，不以空列表掩盖错误。包安装元数据不能证明服务正在运行，不能据此显示绿色运行徽标。应用目标须验证路由及 ACL；无权限/无入口的包不能盲目生成启动按钮。正式接口和安装验收留给后续阶段。

首页应用目录适合进入页面一次读取并缓存、面板打开或安装完成时刷新，不为每个图标设独立轮询；收藏上限6个。当前合成目录普通9项，大量场景33项，未创建目录轮询。原图继续唯一统计采样，其他可见模块沿用既有有界协调器。

任务树：五入口归位 → 移除 A 侧栏/操作台 → 模块隐藏自动收纳 → 模块编辑取消/应用及导航 → 当前多端与状态自检。
验收：五个入口和八个工具可访问；默认 A 无独立快捷栏、无五入口底栏；隐藏模块时入口不丢失、不重复；图表继续真实绘制且不重复采样；设备点击与查看全部语义不变；主路由权限不受视觉组织改变；桌面/平板/手机与320px英文无横向溢出，模态不越过系统菜单边界。最多3次优化，证据另存 `docs/archive/evidence/m66/contextual-actions/`。此前 canvas/system-boundary 结果保留为历史。

## 首要设计边界：系统菜单保持原样

左侧菜单属于系统宿主，Quickstart 只能修改右侧页面内容。菜单项、层级、顺序、图标、样式、宽度、展开/折叠、权限和系统路由均不属于本次设计范围。首页模块选择与布局配置只作用于右侧内容，不包含系统菜单；页面工具不得冒充、替换或遮挡系统菜单。

之前 A/B 的新增左侧工具栏退出当前方案；当前 A 进一步撤掉独立快捷栏，B 对照的工具仍在右侧内容区右边。C 的底部操作台、评审切换条、编辑器和设备详情遮罩也限制在右侧内容区域。这里的快捷入口只是页面内常用操作，不能演变成第二套系统菜单。

用户提供的截图只包含内容区，未包含系统菜单。5180 独立预览因此用明确标注、不可操作的宿主占位区表示边界；桌面暂预留200px用于检查可用空间，不是系统菜单宽度提案，也不伪造菜单项。手机预览不显示占位区，真实菜单的移动端行为仍沿用系统。正式集成使用宿主实际可用宽度，不能将占位区或预览样式发布为系统菜单。

本轮任务树：确认宿主/内容职责 → 纠正 A/B 工具位置 → 约束浮动控件与遮罩 → 当前多端浏览器自检 → 更新唯一设计基线。
验收标准：A/B/C 都只设计右侧内容；没有可编辑的系统菜单项；布局/主题/设备导航不改变占位区；桌面浮动条、编辑器、配置面板、设备详情不越过边界；桌面/平板/手机无横向溢出，原图、五个入口、八个工具和设备详情仍可用。证据单独保存到 `docs/archive/evidence/m66/system-boundary/`，不覆盖前一轮历史结果。

## 产品组织

顶部只承担品牌、当前连接状态、主题与自定义，不承担五个快捷卡片。流量图成为第一视觉焦点，配置工具拥有独立位置。设备摘要跟随主视觉，展示身份与状态，点击进入现有完整管理页和同一 deviceId 的详情。系统、磁盘、共享、Docker、下载和远程访问独立选择。

页面分为三个稳定职责：导航（去哪里）、主视觉（当前网络如何）、模块内容（设备/资源/服务）。设备清单增长仅改变计数，首页仍展示桌面6台/手机3台，不扩大高度来挤走操作入口。能力与状态沿用领域基线，在线不等于允许联网，DHCP分配权独立判断，DNS跟随路线。

## 任务树与验收标准

1. 信息与视觉重组：顶部清爽→五入口移位→原图保留→配置独立→模块分类。验收：全部旧入口有去向；原图组件无视觉改写；摘要不是插到原图和配置工具之间的大块内容。
