# 刷新诊断与本轮方案

当前B d74e6d4正常刷新已用home-refresh-review.cjs复现断言失败：390/448ms时两条home-config-state分别显示“首页布局：正在校验路由器配置…”和“应用工具：正在校验路由器配置…”，首行top232.59375px；487ms两条消失，top125.59375px，净上移107px。与此同时11个默认控件（含networkInterface、末尾system）切换到用户已保存的10个控件（system位于首行右下，networkInterface隐藏）。见baseline/refresh/report.json。

排序假设：1）loading提示条插入文档流造成107px跳动；只隐藏它们应使这个位移消失。2）配置初值为内置推荐，异步读回会替换布局；只隐藏提示仍会闪默认控件。3）下方各业务控件的小“读取中”再扩展，造成局部高度变化，不能当成前两项唯一原因。三者已向用户说明。

probe-hide-banners只在浏览器注入隐藏状态条的CSS，不改产品代码：提示条断言通过，但紧接着默认控件ID断言失败，确认两项独立存在。baseline-slow延迟两份设置读取1200ms，把同一画面保留便于截图，pending.png已实际打开；不是依靠HTTP200判断。

第一候选：仅首次等待layout/launcher两份有8秒截止的首页设置，保持已有业务与软件中心独立并行读取；顶部保留，内容区显示无虚假业务数据/模块/操作的静态中性占位，800ms后才显轻量加载文字。实际宽度测得后才渲染保存的响应式行，避免手机先显示桌面结构；未就绪不显示“空首页”。首轮成功/失败结束后解除占位并锁存，显式重新读取不重新盖住整页。正常检查文字不进入文档流；失败/权限/损坏/未来版本依旧说明并保持原只读/恢复入口。默认首页只作为明确读取异常后的既有临时兜底，不冒充已保存布局。不新增浏览器持久缓存，不自动覆盖配置。

本轮直接处理“全局提示条+错误默认布局闪现”。已有业务数据尚未完成的局部自然高度变化另行测量记录，不宣称整页全部DOM高度绝对不变，不用全页业务Promise.all或固定DOM高度掩盖问题。正式设计最终布局/字体/控件不改。
