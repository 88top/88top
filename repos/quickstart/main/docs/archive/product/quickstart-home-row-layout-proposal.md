## 判断与官方参考

建议将首页从几块独立布局改为统一的“有序行＋行内比例＋模块最小尺寸＋窄屏自动拆行”。用户控制分组、顺序、比例、行高与显隐，系统负责适配实际可用宽度。这是结合当前 Quickstart 组件作出的设计判断，不是某个第三方库现成提供的完整产品规则。

相近模式的原始来源与边界见 [研究记录](quickstart-home-layout-research.md)：

- [Home Assistant Sections](https://www.home-assistant.io/dashboards/sections/)：网格分区、拖动与尺寸调整；[卡片尺寸契约](https://developers.home-assistant.io/blog/2024/11/06/custom-card-sections-support/) 包含默认/最小尺寸。借鉴有约束的自由，保留阅读顺序；不默认采用 dense 自动补洞。
- [Grafana panel layouts](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard/#panel-layouts)：Custom 支持手动位置/大小，Auto grid 支持最小列宽、最大列数、行高且不允许手动单卡缩放。Quickstart 采用自己的组合规则，不能把这两种 Grafana 模式说成同一个现成功能。
- [GridStack Responsive](https://gridstackjs.com/doc/html/interfaces/Responsive.html)：可按网格容器而非整个窗口确定布局。其拖动缩放能力可供未来评估；是否采用库与产品行模型是两个决定。

## 当前代码缺口

`CanvasHome.vue` 分别安排网络主视觉、应用区与内容模块。`canvas.css` 对网络区使用特定宽度和独立高度，`canvasModules.css` 对其他模块使用12列跨度；`canvasLayout.ts` 把连接/工具标为 fixed。它们不是同一个可自由分组、同排等高的布局体系。

当前卡片响应式主要依赖窗口断点；设备摘要还按窗口宽度选择3/6项。用户把某张卡片调窄时，窗口仍然很宽，卡片内部可能继续使用宽版布局。仅开放百分比而不调整卡片尺寸契约，会重复出现拉长、留白、截断或内容溢出。

原曲线、设备身份、业务请求和权限语义可复用，布局容器及组件内部的窄版呈现需要调整。系统左侧菜单继续保持原样。

## 行与宽度规则

1. 每一行是一个有序分组。卡片可在同一行调整比例，也可跨行移动；行可整体排序。
2. 同排卡片分配的是扣除卡片间距之后的内容宽度，比例总和100%。拖动分隔线时相邻卡片一起变化，不允许只把某张卡片改成80%后导致总和超过100%。
3. 用户界面提供50/50、60/40、2/3＋1/3等比例预设，并允许分隔线拖动；建议先按5%吸附，旁边实时显示比例。也提供数值输入/键盘调整，不要求触屏用户精确拖动。
4. 比例表达宽屏偏好；每个模块最小可读宽度是硬约束。临界宽度允许受最小宽度限制而调整实际比例，无法同时满足最小宽度时拆行。编辑预览显示实际结果，不能悄悄压缩字体或越界。
5. 单张卡片独占实际行时默认占满宽度。隐藏卡片后同组剩余卡片重新分配空间；空行不显示；同一个业务卡片默认只出现一次。
6. 自动布局保持从上到下、从左到右的用户顺序，不跨组补洞或随机搬移。窄屏只改变呈现结果，不覆盖用户保存的宽屏分组与比例。

布局依据系统菜单右侧内容容器的实际宽度，不能仅用 window.innerWidth。设容器为 W、行内间距为 G，若两张卡的最小宽度之和加 G 大于 W，则必须拆行。示例最小宽度480/320px、间距20px时，容器少于820px会拆行；这些是原型起点，需要真实组件和语言布局验证，不是冻结参数。

多卡行从左向右分成可满足最小尺寸的连续子行，再在子行内按权重分配宽度。没有绝对定位、瀑布流补洞或按数据更新频繁改变位置。宽屏恢复后使用原分组重新排布。

## 同排等高与内容规则

同排等高应由一份行高控制，避免某张卡的长内容把整行撑大。建议提供紧凑/标准/宽松三个高度档位，起点可为240/320/400px；不满足模块最小高度的档位不可选。应用等轻量独占行可用受内容数量约束的自动高度。

所有同排卡片填满该行高度。图表按容器重新计算尺寸；连接信息宽时可用双列，窄时切摘要；设备按卡片自身宽度与高度选择有界的摘要数量，提供查看全部；长文本/多磁盘展示摘要与明确详情入口。常规首页避免每张卡各自出现滚动条，不通过缩小字体或隐藏关键错误来适应尺寸。

网络连接的协议详情、磁盘完整列表、诊断等通过右侧内容内的抽屉/弹层展开。加载、空、错误、旧版本和能力缺失保持卡片位置及尺寸，不因请求状态自动消失或放大。安装状态不能充当运行状态，设备在线不能充当允许联网。

响应式拆行后，“同排等高”只对当前实际同排成立。单列时，连接卡可恢复紧凑推荐高度，图表保留适合手机的高度，不把桌面的320px等高强加给每一张小卡。横向比例偏好保留，重新变宽后恢复。

## 默认布局建议

以下为下一轮原型起点，均可编辑，不表示强制默认：

| 行 | 卡片与宽度偏好 | 高度 |
|---|---|---|
| 1 | 网络流量60%＋网络连接40% | 标准，同排约320px |
| 2 | 应用与工具100% | 自动、紧凑 |
| 3 | 局域网设备约2/3＋系统状态约1/3 | 标准、同排等高 |
| 4 | 磁盘信息60%＋存储服务40% | 同排，按可容纳摘要的档位 |

默认网络卡较当前更均衡，连接卡内部也需重新组织，以有意义的信息密度利用新增宽度。用户可移走/隐藏右侧业务卡片、调整分组和顺序；系统菜单和编辑/恢复入口不参与自由拖放，避免无法找回自定义能力。首页模块选择与软件安装/业务策略权限分离。

## 编辑体验

普通浏览模式不显示布局边框、比例、拖动手柄或尺寸控制。点击自定义首页后：

1. 展示行边界和卡片手柄；选中行后显示比例与高度档位。
2. 卡片之间拖动分隔线调整比例，边拖边看到最终内容；最小宽度位置有明确限位。
3. 拖动卡片可交换位置、加入已有行或新建行，落点预览标明“加入此行/另起一行”。行首手柄用于整体排序。
4. 在模块清单开关卡片；提供桌面/平板/手机预览，但不要求用户维护三套布局。
5. 草稿应用/取消、撤销和恢复推荐布局明确区分。移动端优先按钮排序与比例选项，拖动作为补充。

布局偏好不是设备策略事务。正式保存只包含布局配置；保存失败应明确提示、保留草稿并允许重试，不能声称已同步。原型仍可只用本页内存，待产品确认后确定正式保存作用域。

## 实现与资源边界

模块注册表声明稳定ID、组件、最小宽高、推荐高度、内部紧凑布局及所需数据。布局配置独立保存行顺序、行高和卡片权重/显隐，带 schemaVersion；不保存运行时测量的坐标、当前 IP、设备策略或观测数据。

示意结构：

```json
{
  "schemaVersion": 1,
  "rows": [
    {"id": "network", "height": "standard", "cards": [
      {"id": "traffic", "weight": 60},
      {"id": "connection", "weight": 40}
    ]},
    {"id": "applications", "height": "auto", "cards": [
      {"id": "applications", "weight": 100}
    ]}
  ]
}
```

建议先使用 Vue＋CSS Grid 与一个集中布局协调器。任意百分比可用权重实现，无须为了百分比强行限制为12列离散跨度。容器尺寸变化由 ResizeObserver 驱动，拖动过程合并到动画帧，避免测量/写样式循环；原图复用 resize 能力。根据实际卡片宽度切换内容版本，不能仅按视口断点。

只有产品确实需要自由二维摆放、碰撞挤占、复杂吸附时，再评估引入 GridStack，并先核验项目 Vue/构建工具兼容、包体和触屏表现。首页约十个异构模块、有明确阅读顺序，当前用有序行模型更易解释和恢复。

布局计算发生在浏览器。路由器只保存少量偏好配置，不新增统计/历史/后台扫描。布局编辑不产生策略写入，移动卡片不创建新轮询；继续共享现有身份、缓存和读取协调器，隐藏暂停/卸载清理。

## 建议实施顺序与验收

1. 统一行模型与模块尺寸契约：先接入流量/连接、应用、设备/系统三个组。验收为同排等高、改变宽度不造成溢出、所有模块采用相同布局规则，原曲线与设备语义保持。
2. 原位编辑：拖比例、跨行移动、整行排序、档位高度、显隐及草稿取消/应用。验收为比例总和正确、最小尺寸有效、编辑前后入口可达、撤销与恢复可靠。
3. 响应式与资源收口：按实际容器逐步缩窄/变宽；验证中英文/深浅、错误/能力缺失、多设备/多应用、多磁盘。验收为临界点不抖动、阅读顺序不变、恢复宽屏还原偏好、隐藏状态和编辑过程无重复采样，不覆盖系统菜单。

每阶段先列任务树与具体测试，再实现、自检，最多优化3次；新证据单独归档，不将此前原型通过结果当作新布局引擎验证。以上为后续建议，当前未实施。
