## 已确认原因

1. `web/src/home/HomeLayout.vue:63` 将提示作为首页根节点的直接子元素。
2. `web/src/home/directEdit.css:26` 只在编辑期间令其 fixed，左偏移依赖 `--design-system-reserve`。
   当前正式页面该变量为空，回退 0。2048px 桌面上提示框 x=16..696，内容区从 x=240 开始，文字 x=35..167。
   文字所在位置被 `.main-left` 覆盖，截图只露出空框尾部。
   浏览器单变量设为 240px 后提示框 x=256，文字显示正常，截图已打开比较。
3. 撤销、取消、排序等消息使用同一 `notice` 字符串，没有自动到期机制。
   未执行相关动作或开始新编辑时字符串为空，因此用户感到偶发。
4. 取消编辑后失去 `.ordered-editing` 定位规则，回到 `orderedHome.css:7` 的普通段落布局。
   手机端提示及下边距合计撑开约 65px，确实存在操作消息进入内容流的问题。
5. 第五行是独立的草稿占位：`layout/slotLayout.ts` 的移动与隐藏保留来源空槽；`normalize` 在完成流程整理空行。
   当前 B 已保存的第五行仍有系统信息。复现使用隐藏草稿，不代表用户截图的全部移动历史；截图中系统信息已在第一行。

- 将布局操作提示与行布局彻底分开，编辑中、退出编辑后都不占业务内容高度。
