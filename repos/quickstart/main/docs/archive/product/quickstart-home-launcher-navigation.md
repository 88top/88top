# 应用启动台：URL、返回恢复与动态入口契约

## 首页测速与FastNet动态入口（2026-10-19）

FastNet app-meta增加entry.sh/META_UCI能力；应用工具中的FastNet沿既有统一动态入口流程。首页网络流量的“测速”保持两字，通过同一稳定启动宿主激活，区别仅为业务准备流程和返回来源：等待现有installed首读结果，不另起初载读取；确认已安装且脚本返回真实运行+有效Web时同窗直达，不弹启动台。不自动启动服务或执行测速。

未安装时复用原app-meta-fastnet检查、用户确认安装、安装接口和轮询；安装成功先进入原LuCI配置。已安装但未运行/无Web、或旧meta没有动态能力时，提示用户是否继续检查安装并打开配置；已安装不重复安装。目录/脚本未知、失败、无权限、超时不误判未安装，原位错误提供显式重试/关闭。脚本解析独立5秒截止，不把安装过程错误地当作5秒解析。取消后的检查不能迟到弹出安装确认；已明确开始的安装仍由原安装流程执行，不声称取消提示等于撤销安装。

测速与首页固定/完整库共用激活去重、取消和最新来源规则；完整库打开会取消待处理测速。首页返回记忆仅额外允许fastnet的traffic来源，恢复网络流量测速按钮和原滚动，不依赖用户是否固定FastNet。当前历史项保留，不新增panel或保存Web URL/token。详情按钮外观修正及现有导航规则继续有效。[任务、测试与设备证据](../evidence/m70/fastnet-entry/status.md)。

## 浏览行为

默认在当前标签页打开已安装应用。从完整启动台打开时，浏览器返回后恢复窗口、分类、分页、搜索、滚动和焦点；从首页固定入口打开时返回首页。内置工具保持原表单/动作；自定义链接保留现有明确的新标签页语义。“新标签页打开”辅助入口没有作为本次新增功能实现。

例：`/cgi-bin/luci/admin/quickstart/?panel=applications&tab=apps&page=1`。浏览状态使用首页query，不新增需要LuCI深路径转发的页面；URL只允许白名单面板/分类及有界页码。直接访问、刷新、浏览器前进/返回均可还原浏览窗口。私有搜索词、滚动、上次焦点应用ID放当前历史项的临时状态，合并保留Vue Router自身历史字段，不写路由器布局/收藏配置，不保存目标服务凭据或URL令牌。

| 操作 | 历史及状态 |
| --- | --- |
| 首页点查看全部/进入浏览启动台 | push一次带panel的URL |
| 首页点固定应用 | 保持首页URL和当前历史项，图标原位loading，成功同窗直达；不打开完整启动台，不创建panel参数 |
| 切换全部/已安装/工具/链接、分页/搜索 | replace当前浏览状态；搜索等细节不进query，不每次输入都加历史 |
| 点击应用 | 先保存本历史项的分类/位置，再在当前页assign真实目标；不能先按“关闭窗口”处理或替换掉启动台历史项 |
| 应用页返回 | 根据URL及历史状态恢复窗口；兼容BFCache复用和完整重载，目录按单owner规则读取 |
| 浏览器返回关闭窗口 | route状态驱动关闭UI并释放inert/滚动锁，无额外push |
| ×/Escape | 自己push的窗口项可返回原首页；直接粘贴/书签打开则replace移除窗口参数，避免离开Quickstart |
| 编辑中离开 | 保留原未保存确认，并覆盖query更新/浏览器返回；URL只恢复浏览态，不把编辑草稿冒充已保存 |

滚动与焦点待对应应用可用且渲染后恢复；设备应用变化时夹紧页码，焦点目标消失时回到搜索或关闭按钮。恢复导航不能触发安装、启动或保存。外部应用自身后续创建的历史由其管理，Quickstart保留的是离开时的启动台历史项，不承诺控制外部应用的整个历史栈。

返回位置取决于来源：首页固定应用返回首页，恢复该图标焦点和页面滚动；完整启动台中打开应用返回启动台，恢复分类/搜索/分页/滚动。首页返回信息仅在当前history.state.qsHomeEntry保存有界应用ID/scroll及原auto/manual滚动模式，不含目标URL或凭据，不写配置。稳定宿主拥有单一解析请求，响应式卡片只呈现状态。首页失败/5秒超时显示控件内的非模态小提示，提供重试/原配置/关闭；提示绝对定位，图标loading和错误均不改变控件高度。Escape取消并丢弃晚结果；显式打开“查看全部”也取消旧首页请求。自定义域名链接保留现有明确的新标签页语义，直接打开，无入口脚本或中间窗口。

首页返回由单一、有界owner处理。待布局配置、启动台及目标所在行/上方控件的首轮读取有明确成功或失败结果后，再采样目标位置/尺寸连续三帧稳定并恢复滚动与焦点；数据owner只提供现有结果的就绪状态，不新增请求。页面与各控件仍独立呈现，下方无关磁盘/服务不阻塞返回。仅等几帧不能证明慢响应已结束，禁止固定补偿8px或通过放宽断言处理。恢复期间暂管原生scrollRestoration和CSS锚定；成功、10秒截止、卸载或用户pointer/touch/wheel/keyboard输入均清理订阅并精确恢复原模式、inline值与priority，用户输入立即放弃待恢复记忆。自然高度测量也只在同步临时样式期间关闭锚定并在finally还原，避免后续测量选择临时布局锚点。测量、等待和几何数据不写用户配置，不常驻禁用浏览器锚定。

修复前：HomeApplications的browserOpen/browserTab/search/libraryPage均为组件内存；openBrowser会清空搜索/分类/页码，activate在导航前调用closeBrowser；全部入口都不改URL。当前实现以useLauncherRoute绑定独立host-only宿主与Vue Router，launcherRouteState负责有界纯契约，卡片请求宿主，不把状态绑到响应式卡片。系统左侧菜单不变。

## 动态入口应在点击时解析

所有已安装应用启动位置（完整库、首页固定等）走同一个激活入口：保存返回状态 → 根据能力按需解析目标 → 跳转。首页初载仍只读取installed一次及本地图标，不为展示图标执行全库entry.sh；不把运行状态或动态URL写进收藏。

有entrysh能力的应用当前复用现有软件中心`POST /cgi-bin/luci/admin/store/entrysh`，携带token GET取得的真实CSRF token、单个合法应用ID、当前访问hostname及update=1。源码确认该接口筛选package后只调用`status`，可能加缓存锁和更新/tmp缓存；不等于前端可执行任意shell，也不能省略package使其扫描全库。强制新鲜状态避免旧缓存仅按UCI mtime失效而遗漏服务启停。单次点击解析5秒截止，失败明确重试和原配置入口；同应用进行中重复点击不追加请求，另一应用/关闭/隐藏/离开会取消旧结果，不执行晚跳转。该能力与已确认的只读列表GET分离，token和动态服务URL不写配置/历史状态或日志。

| 解析结果 | 动作 |
| --- | --- |
| 确认运行且有效Web入口 | 当前窗口打开服务Web页面 |
| 未部署/未运行，或无Web入口 | 打开原LuCI配置入口/显示原业务说明，不擅自启动或安装 |
| 读取失败/超时/无权限 | 留在窗口，显示重试和可用的原配置入口，避免盲跳死地址 |
| 没有动态解析能力 | 使用原元数据entry |

解析需校验HTTP、业务code、结果数组、匹配app ID、协议和目标结构；只接受HTTP(S)或约定的安全本机路径。LuCI的空错误表可能编码为`[]`或`{}`，仅这两种空容器有效，非空/缺少/标量错误均失败。`:5003`是端口描述，不是可直接跳转的URL，应以当前访问路由器的hostname、脚本协议及合法端口规范化，处理IPv6，不写死测试IP、不误用用户电脑的127.0.0.1。域名/反向代理访问时端口不一定对用户可达，需保留原配置入口，不能把设备本机监听等同于浏览器可达。解析进行中防止重复点击、晚响应覆盖和重复跳转，失败不关闭窗口；不把状态请求变成自动start/stop操作。

脚本状态与已安装身份分开。安装元数据的flags含entrysh且uci身份合法时声明解析能力；无静态entry但有该能力也可启动，仍按真实解析结果决定目标。纯静态应用不请求token/status。内部工具及自定义链接保持原动作；所有已安装应用的首页固定和启动台入口委托同一宿主激活。

## KSpeeder例子的实际核查

实施前用户指定的`istoreos-app-hub/apps/istoreenhance/app-meta-istoreenhance/entry.sh`中，status只用`[ -x /usr/sbin/iStoreEnhance ]`判断running=true，再读取adminport，返回web=`:端口`、protocol=http、href=原LuCI页。**可执行文件存在不是服务运行证据**，因此先由应用侧修正状态语义，不能在Quickstart统一层硬编码此应用的进程规则。现有start/stop分支实际会调用init服务，打开图标不能调用这些分支。

上述为起点问题，当前已在应用仓库afdc652修复：deployed依可执行文件，running依procd实例真实状态，停止时不返回Web，读取失败明确失败，端口有界；meta release为0.8.4-r2。B仅原子替换脚本候选且实际SHA/procd/配置未变核验通过，未重启服务或声称包元数据已升级，见script-round-2证据。前端没有硬编码KSpeeder进程名。

2026-10-19实施前只读核查：procd报告istoreenhance实例running=true、命令adminAddr=:5003，UCI端口5003；不带LuCI登录凭据GET`http://192.168.30.244:5003/`得到HTTP200/html。当时尚未执行entrysh POST/修改应用仓库。后续已修复脚本、核验opkg/APK单应用协议，并在B真实点击进入KSpeeder仪表盘及返回启动台；这仍不代表KSpeeder登录后功能或Docker加速业务验收。

现行文档另作事实纠正：software-center的configured()实际上只检查`/etc/config/<uci>`是否存在；执行入口status脚本的是entrysh POST。此前把configured描述为会执行入口脚本不准确，历史归档保留，但现行规范按实际源码区分两者。

1. URL与返回恢复：纯解析/序列化、稳定宿主路由同步、历史项/搜索滚动恢复、关闭与未保存保护、所有已安装应用激活位置统一。证据目录预留`docs/archive/evidence/m70/installed-apps/navigation/`。验收浏览器Back/Forward、刷新、书签直达、直接关闭、分类/分页/搜索/焦点恢复、手机返回、BFCache及完整重载；不新增目录轮询、不改变共享收藏和布局。先实现这一阶段即可改善当前体验。

每阶段先冻结候选，最多三轮优化，保留失败，实际打开截图并真实登录态验收B。脚本封装、URL本地验收及B入口验收各在第二轮通过；无需第三次产品修订。完整重载返回已实测，persisted pageshow恢复路径已用明确生命周期事件核验；本次自动化原生返回事件的persisted=false，不宣称浏览器实际命中BFCache。APK设备仅验证单应用status协议，不把目录/PNG/协议检查当成完整Quickstart验收；部署/构建/跨仓库改动沿原保护和发布规范。当前实现状态、失败与最终验收以执行证据为准，历史“仅建议”段落不能代替实际运行结论。
