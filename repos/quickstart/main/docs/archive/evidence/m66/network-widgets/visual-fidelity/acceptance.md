# 用户截图反馈：网络连接标准形态视觉对齐

2026-10-16。M66.32～34的功能／边界技术检查通过后，用户指出原版和新原型的字号、内容排布不同。本轮独立记录反馈修正，不将上一候选的技术通过视为视觉还原通过，也不覆盖其失败或优化次数记录。

## 目标与任务树

1. 对照：核对用户两张截图、正式Card.vue与NetworkConnection.vue、原型组件和CSS。
   - 标题16→13px、正文约14→10～12px、设备管理按钮12→10px。
   - 时长移到底部、协议移到状态副标题、DNS来源换行；标准卡被做成摘要式排版，留白失衡。
   - IPv6与时长差异来自合成fixture，不是实机状态改变。
2. 修正：只恢复标准形态的原视觉尺度与信息分组。
   - 复用原地球／成功／设备拓扑／眼睛SVG组件，沿用原字号、边框按钮、分隔线、状态时长徽标、标签与地址分行。
   - IPv4保留接口名及协议标签；DNS来源与标题同列。完整连接详情保留为次级入口。
   - 摘要形态保持独立紧凑呈现；状态映射、隐私定时器、业务动作、布局事务不重做。
3. 复验：同数据同尺寸审图、响应式、原状态与隐私操作、受保护业务源文件检查；在5180提供当前构建。

## 验收标准

- 对照场景使用wan／静态网络／无IPv6／手动DNS 192.168.30.1／接口秒数312357，与用户原截图的字段条件对应；这是模拟数据。
- 382×320标准卡：标题16px、正文／状态14px、设备入口12px；时长在状态行，协议在IPv4行，DNS来源在标题旁，地址在下一行。
- 窄容器标题14px、正文13px，不能缩到摘要字号；320px起中英文无卡片或页面溢出。
- 缺IPv6继续使用已约定的“暂无地址”，不根据没有地址推断协议未启用；时长提示明确为接口在线时长。
- 普通双栈fixture保留，IPv4／IPv6分别默认隐藏与60秒收回、异常动作、详情、摘要仍可用；正式业务源码保持原样。
- 失败后最多优化三次，保留每次检查；用户体验确认单独记录，不自填通过。

## 当前检查

本轮保留初检及三轮优化记录；结果按下方具体候选区分，上一候选PID3928和资源清单为历史记录。

初检同尺寸还原与隐私操作通过，390px视口的对照场景出现8px竖向溢出。优化1：窄容器字阶断点由内容宽320px调整为340px（不影响382px对照卡的16／14px字号）；多DNS保留有界单行预览、完整详情可达。宽矩阵初轮在更新构建时中断，只保留诊断记录，不作为最终候选结果。

优化1复验：390px通过，768px视口单列280px槽位仍有8px竖向溢出。优化2：标准卡按容器高度压缩短槽位的间距，保持正文可读字阶，不更改用户行高、模块尺寸声明或摘要形态；320px高对照卡仍保留舒展间距。

优化2复验的四组还原／最小尺寸、十四组交互、六组输入、四组资源、契约与业务源码保护通过。进一步直接读取当前baseline原版页面和新画布的computed style，确认原版Arial／Microsoft YaHei字体栈被Inter等画布字体栈替换；并非只有字号差异。优化3：标准卡恢复原字体栈、标题和地址颜色变量，摘要及其他控件不受影响。最终候选需在此改动后重新构建，不能沿用优化2资源指纹。
