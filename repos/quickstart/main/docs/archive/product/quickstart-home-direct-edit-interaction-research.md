# Quickstart 首页：从表单配置转向就地编辑

执行更新：用户已授权实施M66.13～18，当前实现及最新自检见[阶段状态](../evidence/m66/direct-edit/status.md)与[R规格](quickstart-home-ordered-prototype-spec.md)。下文为实施前研究记录，其中“已有/尚未实现”均对应研究时的3b2beca基线，不能作为当前实现状态。

研究日期：2026-10-15。范围：当前 R 有序首页原型的下一轮交互方案；仅建议，不代表方案已经实现。用户已认可产品功能定义，并要求先提交当前代码；此次反馈明确指出编辑交互仍需较大优化，因此不能记录为当前视觉、编辑体验的最终人工验收通过。

当前功能基线已本地提交为`3b2beca`（feat: archive Quickstart ordered home design prototype），未推送；本文为提交后的交互研究建议，尚未改动当前5180界面。

用户随后认可方向并要求定义完整实施阶段，计划见[M66.13～M66.18](quickstart-home-direct-edit-milestones.md)。此认可确认交互方向，不代表新界面已实现或最终体验已验收。

## 建议结论

推荐 **在真实首页上编辑，拖动负责位置，分隔线负责比例，卡片旁的轻工具负责其他操作**。进入“自定义首页”后，用户仍然看完整首页；去掉常驻的大块参数表单。保留现有有序行、有限模板、尺寸约束、应用/取消/撤销，不引入自由坐标和任意嵌套。

“酷”来自操作对象直接响应、落点提前展示结果、松手后平滑归位；不依赖增加复杂手势。第一次使用就能看到可拖手柄和分隔线，手机及无法拖动的人也能通过点击完成同样操作。

下文“官方事实”来自已访问的一手资料；“Quickstart 建议”是结合本项目的设计判断，并非第三方结论。

## 三种可选交互

以下复杂度是本项目相对估计，不是开发排期承诺。

| 方案 | 操作方式 | 美观与直观性 | 相对实现成本 | 建议 |
| --- | --- | --- | --- | --- |
| A：就地编辑 + 有限落点 + 轻工具 | 拖卡片到明确目标；拖分隔线；选中行或卡片后出现少量工具 | 操作直接作用于真实页面，编辑工具只在需要时出现 | 中；可保留现有布局模型和大部分校验 | **推荐主方案** |
| B：模板优先 + 点击放置 | 先点整行/两列/三列/单侧堆叠缩略图，再点空位选模块；可点卡片后再点目标交换 | 学习成本低，移动端稳；操作次数多于直接拖动 | 低至中；现有模板和分配逻辑可复用 | 作为 A 的基础与非拖动操作路径 |
| C：自由网格 + 任意角落缩放 | 类似通用仪表盘画布，任意移动和缩放每张卡 | 初看自由，但用户需要自己维持对齐、阅读顺序和间距 | 高；涉及碰撞、重排、响应式坐标映射及新尺寸契约 | 暂不采用，会改变已认可的有序行产品模型 |

A 与 B 可以统一为同一套交互：拖动和点击放置调用同一条布局命令，用户无需选“高级/简单模式”。

## 推荐方案如何操作

### 1. 编辑态保留完整首页

普通首页仍保持干净。点击“自定义首页”后，只增加一条紧凑编辑栏：添加模块、撤销、恢复推荐、取消、完成。当前草稿的语义继续保留，完成前不写入已应用布局。

卡片编辑态显示轻边框和短标题手柄；鼠标悬停、键盘聚焦或触摸选中时强调工具。不能把操作入口只藏在 hover 里。行模板入口附在本行边缘，点击后出现五张结构缩略图；不再把整屏卡片压到一大块表单下面。

浮动工具应限制在右侧内容区，靠近视口边缘时自动换边；手机使用底部面板，避免复现320px弹层越界问题。不新增或占用左侧系统菜单。

### 2. 卡片只提供三类明确落点

- **卡片中心：交换。** 拖动时目标卡出现“与系统状态交换”及轮廓，不暗中触发挤占或嵌套。
- **已有模板的空位：移入。** 使用虚线槽位展示模块名称与可用尺寸；填入后源位置留空，是否显示空行沿用当前草稿/应用清理规则。
- **行与行之间：另起一行。** 行间出现细插入线，文字明确“移到这里，独占新行”；整行手柄拖到行间则只调整整行顺序。

不把卡片的四个边缘同时变成自动“左插入/右插入/上下堆叠”手势。改成三列或单侧堆叠时，先在本行选择结构缩略图，再移动卡片，减少落点歧义和实现分支。

超出最小宽高、同一模块重复或紧凑摘要不支持的组合，应在拖动预览阶段标示不可放与具体原因；松手不改变布局。不能先吸进去，再把内容裁切或悄悄提高行高。

拖动过程中只更新占位预览，正式命令在确认落点后一次提交，撤销一次就恢复拖动前状态。Escape、pointercancel、失去目标时恢复原位；预览过程中不重新请求业务数据。动效采用轻量位移和阴影，支持系统减少动态效果偏好。

### 3. 比例直接拖，精调再展开

同排卡片之间显示可辨认的分隔线，拖动时就地显示“60 / 40”；接近常用比例时吸附。三列只调整相邻两列、保留其合计，避免牵动第三列。上下组合拖水平分隔线，最小高度继续来自卡片契约。

点选分隔线或行工具可以直接点“均分 / 主次 / 次主”等小图示预设；精确百分比放在可展开项，不常驻首页。行高先提供紧凑/标准/宽裕等视觉档位及小预览，必要时再显示像素值，不在第一版增加任意底边缩放。

### 4. 轻工具按对象出现

选卡片：显示“移动”“隐藏”；隐藏后用短提示提供撤销。选行：显示结构图、尺寸、上移/下移和收起。添加模块打开已有模块清单，先点添加后进入目标选择，保留“新建一行”这个清楚的默认选项。

“更多”只收纳不常用的精确设置。快捷动作数量保持少，不同时展开卡片、行、页面三套大型工具栏。

### 5. 手机和键盘操作等价

手机默认点击选中 → 点击“移动” → 页面高亮合法目标 → 点击目标确认；底部保留“取消移动”。用户不必持续按住跨屏拖动，正常纵向滚动不被整张卡劫持。可拖手柄是补充，不把长按作为唯一入口。

键盘使用 Tab 到卡片工具，Enter 进入移动，再按 Tab 选择已标明名称的目标并确认，Escape 退出；移动后焦点回到卡片。分隔线支持相应方向键调整，并播报当前百分比和限值。点击移动、拖动移动、键盘移动共享相同结果和撤销行为。

窄屏当前看到的是响应式单列，不能把“视觉相邻两张卡”误认为原本同一行；移动目标需要显示“第2行 · 第1列”等结构摘要。本阶段移动端优先调整模块与行顺序；桌面列比例与模板仍在明确的结构面板操作，不让单列外观自动改写桌面布局。

## 现有能力和新增工作必须分开

根据当前源码核对，以下能力已经存在于原型，不应包装成新实现：

- [OrderedHome.vue](../../../web/src/design/OrderedHome.vue)：HTML Drag and Drop 在当前可见卡片间交换；列宽与上下比例已有 Pointer Events 分隔线及方向键；模板、选择器、整行上/下移、模块隐藏/恢复、草稿、撤销、应用和取消已存在。
- [orderedLayout.ts](../../../web/src/design/orderedLayout.ts)：固定层级、五种模板、模块唯一、最小高度、有限响应式拆行和镜像角色保留。
- [当前原型规格](quickstart-home-ordered-prototype-spec.md)：内存态应用、刷新恢复示例、单侧堆叠紧凑摘要、真实生产接口与持久化尚未接入。

**尚未实现的是**：移走常驻大表单的完整就地编辑；空位与行间插入目标；点击选中再点目标的统一移动模式；跨屏目标选择；支持触摸的卡片拖动适配；与拖动一致的落点预览/不可放原因；上下文轻工具；分隔线完整可访问数值语义；移动结果焦点与播报；取消手势恢复原位的统一协议。已有鼠标拖动不能证明以上路径已通过。

## 架构与依赖选择

优先保留 Vue 数据为唯一事实来源，将交换、移入空位、新行移动、行排序、比例调整写成有限布局命令。输入层只生成意图，先经同一份尺寸/结构校验得到预览，确认后提交一个草稿快照；不要让不同输入方式各写一套改布局逻辑。

第一步可复用已有 Pointer Events 手势层验证比例和有限卡片移动，不立即引入完整画布引擎。如果后续触摸、长页面自动滚动和拖动占位成为主要工程成本，可评估 SortableJS 的手柄、列表间拖动和动画能力。[SortableJS 官方示例](https://sortablejs.github.io/Sortable/) 提供这些能力；但它不会替我们定义有限模板、尺寸校验和键盘等价路径。接入时需适配 Vue 状态，不能让库直接重排 DOM 后与数据顺序分离。

GridStack 官方展示拖动、缩放和响应式仪表盘能力。[GridStack 官方站点](https://gridstackjs.com/) 本项目判断它的通用坐标布局并非当前必要条件：若仅实现上述有限操作，就不应为了手感更好而引入第二套布局事实来源。是否采用第三方库应在小范围输入原型后决定，不用一次替换现有引擎。

## 下一轮原型可测试目标

1. 打开编辑态后，1440px第一屏仍能看到主要首页内容；没有遮住首页的大型常驻表单，普通态没有残留编辑边框。
2. 同一个“交换系统与连接”“移入空槽”“独占新行”任务，鼠标拖动、纯点击、键盘均得到相同布局；每次撤销一步完整恢复。
3. 落点只出现允许的交换、空位、行间目标；改变模板必须通过结构缩略图，不允许意外创建递归容器。
4. 320/390px手机可不拖动完成添加、隐藏、恢复、移动和取消；滚动不误触拖动，工具不越界、不被底部栏遮住。
5. 双列/三列/单侧堆叠比例实时预览，达到卡片最小尺寸时给出具体原因；取消手势不留半成品，变窄后再变宽恢复原比例。
6. 连续拖动与调整尺寸不增加业务轮询器、不导致设备身份重复，不修改左侧菜单、真实策略或路由器设置。
7. 先用“移动一张卡、改一个比例、加一个模块”三个任务做人工体验确认：用户无需查说明即可找到操作，拖动结果在松手前可预测；记录误操作与返回次数。自动化只能证明路径正确，不能代替用户对便利、美观和手感的确认。

建议先完成以上有限交互样机，再决定是否进入正式首页实现；功能定义继续沿用当前已认可基线，不借交互优化重新打开自由布局选型。
