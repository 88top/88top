# opkg/APK应用目录来源比较

范围：用户指定opkg`root@192.168.30.244`、apk`root@192.168.9.140`，比较复用软件中心GET与自建无锁读取接口。本轮只分析，正式首页仍使用已部署的软件中心GET，不改业务代码、不部署、不升级软件中心、不创建统一软链接。旧“自建更合适”的初步倾向以本次两机证据重新评估。

任务树与验收：A读板型/包版本/元数据及实际控制器 → B逐台创建短期root会话、串行3次installed GET → C比对ID/元数据/已安装app-meta包、检查配置保护与销毁会话 → D比较锁、缓存、兼容和失败语义，形成建议。证据须含HTTP实际数组，不能以目录存在或HTTP200代替列表正确。不得调用安装/卸载/更新/configured/entrysh，不持锁注入、不做并发压力，不以测量改动配置。A～D已完成，当前没有需要三轮优化的失败。

## 锁和数据所有权

真实函数摘录：[opkg](opkg-installed-source.lua)、[apk](apk-installed-source.lua)。两版均以阻塞方式获取`/var/lock/istore-installed.lock`，缓存命中也要取锁，持锁检查/读取或重建`/tmp/cache/istore/installed.json`，然后释放。它与安装操作的`/var/lock/istore.lock`、入口脚本的`istore-entrysh.lock`是不同锁；现有源码不能支持“软件安装时始终占着应用列表锁”的判断。不过其他目录读取者竞争或慢文件处理仍可能让列表等待，本轮不证明无竞争等待。

旧opkg实现重建缓存时读取`/usr/lib/opkg/meta`并以`luci.model.ipkg.status(app-meta-name)`过滤。新版APK实机通过统一路径读取`/lib/apk/meta`，按元数据文件存在和mtime构建，不再逐项调用opkg状态。当前API对外契约相同，内部规则由各软件中心版本维护；自建接口需要明确希望沿用哪个版本的语义，不能只换一个目录字符串就声称全部兼容。

这把锁保护目录缓存读写，不是整个包安装事务的快照锁。缓存之外的元数据/包数据库可能正被安装器改变，因此软件中心接口也不承诺强一致的安装事务快照；自建无锁扫描同样不能凭空获得这一保证。

## 两个方案的取舍

| 维度 | 复用软件中心GET | Quickstart自建无锁目录 |
| --- | --- | --- |
| 当前两机兼容 | 已实测通过 | 现有catalog缺旧版路径适配，尚未实现/验证 |
| 业务副作用 | 不安装/卸载/配置，可能写/tmp缓存并加缓存锁 | 可做到只读元数据及包记录，不创建目录/软链接/缓存/锁，不运行入口脚本 |
| 权威语义 | 与用户看到的软件中心列表同源 | 自行承担旧/新软件中心、opkg/APK安装状态及残留元数据语义 |
| 性能 | 当前3次小样本无明显阻塞，首载1次 | 未测，不能以不加锁推断一定更快；重复扫描/状态解析也有成本 |
| 错误表达 | HTTP/JSON失败可识别，但目录缺失可能直接返回空数组，不能可靠区分未安装与目录未就绪 | 可明确缺来源/未就绪/读取失败/局部损坏/真正空列表，并提供有界重读 |
| 缓存新鲜度 | 依软件中心的目录mtime失效逻辑，不能保证覆盖所有原地文件更新 | 可不依赖该缓存，但需处理扫描期间安装/卸载和文件变化 |
| 维护及验收 | 保留现有前端适配、每版本兼容检查 | 增加后端源选择/读状态/错误协议及双环境测试；仍须对照软件中心 |

**当前建议：继续复用GET，不因“存在缓存锁”就另建一套安装目录。** 当前首载一次、控件独立加载、8秒截止和显式重试可沿用；不要增加轮询、逐应用请求或双源合并/静默回退。已有读取失败/权限提示保持；软件中心目录缺失返回空的限制须保留为已知边界，不能在文档中声称已全部区分。

值得改为自建的条件：用户把“后端零文件写入、零显式文件锁”设为硬约束，或真实复现缓存锁等待影响首屏，或确定必须由Quickstart区分目录未就绪与真正空列表且软件中心API不能提供。此时修复现有`app/v1/catalog/`即可，不再增加平行接口：只读识别包环境/来源、限制文件和数量、校验JSON和安全entry，按既定语义核验安装状态；读取竞争时有界重读或明确错误，前端保留原已确认列表并提示过期，不用空数组吞失败。Go侧不调用is-opkg初始化，不创建统一软链接，不直接读软件中心缓存文件绕锁。新增测试需覆盖opkg/APK、无统一路径、缺目录、有效空、损坏项、安装/卸载中变化、权限、取消与资源边界，并分别实机验收。

本次APK结论仅限真实软件中心API/元数据/包状态，不等于Quickstart在APK上完整UI、构建或安装验收完成；没有改动APK设备上的Quickstart。未push/发布/触发Action。
