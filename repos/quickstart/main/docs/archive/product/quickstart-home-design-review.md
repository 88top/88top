### M66.1 独立 Vue 预览与数据隔离

**目标：让现有 Quickstart 组件能在 5180 独立运行，并与真实设备配置隔离。**

任务树：检查 Vite/启动注册/路由/i18n/特性注入 → 独立设计入口 → 示例请求适配 → 预览生命周期切换。

验收标准：

- 使用项目已有 Vue/Vite 工具链、全局组件和样式；设计入口不被正式入口导入，正式构建不包含场景控件或请求替身。
- 首页所需读取接口及读取性质的 POST（如应用检查）由明确的 fixture 清单响应；安装、服务启停和路由配置操作不能请求真实设备。
  预览内需要编辑的状态只在内存中变化；未匹配的接口返回可定位的错误，不能一律返回成功掩盖缺失。
- 5180 绑定 0.0.0.0；start/run/stop/status/logs、nohup+setsid、锁/PID/日志和进程归属保护保持可用；端口被其他项目占用时拒绝启动。
- 验证本机和预定评审客户端的访问路径；跨网段访问失败须记录，不能仅以 localhost 成功宣称用户可访问。
- 本机 npm/Go/Cargo 依赖、构建或测试执行前应用 ssd-build-cache，并核验缓存与实际输出目录；保留项目工具链和发布语义。

交付：Vue 设计入口、fixture 接口清单、启动说明、访问地址与生命周期证据。
证据位置：`docs/archive/evidence/m66/vue/01-preview/`。

### M66.3 设备摘要与布局比较

**目标：在现有 UI 中找到设备摘要的合理位置和信息密度。**

任务树：复用 Card/设备图标/身份呈现 → 有界设备摘要 → 两种位置对照 → 数量与字段切换。

验收标准：

- 可切换“当前首页”“网络区下方、配置工具上方”“快捷入口下方、网络区上方”；布局参数可分享和刷新保留。
- 除摘要位置所需变化外，原首页模块及视觉保持基准，便于明确比较影响。
- 设备数量来自完整库存，摘要数量独立；先以桌面/平板6台、手机3台为评审候选，允许比较并记录调整。

## 以下为首次 HTML 原型的历史分析

以下早期布局、推荐顺序和HTML截图用于保留设计推导，不作为新的Vue原型实施布局。
设备身份、权限、降级与资源边界继续服从唯一产品基线；需要保留的具体建议在M66.6确认。

## 产品经理：首页要回答的问题

用户首先需要知道网络是否可用、有哪些设备、下一步该去哪里；存储用户还需要知道磁盘与常用服务是否正常。
首页按“网络与系统概况 → 设备摘要和常用入口 → 流量概览 → 存储/共享/应用 → 系统信息”安排内容。
设备摘要在推荐方案首屏的主要区域，避免藏在 600px 流量图和多层配置模块之后。

源码检查发现：

| 当前实现 | 产品影响 | 本轮建议 |
| --- | --- | --- |
| `/` 路由为 `web/src/pages/index/index.vue`；设备页为 `/devicemanagement` | 已有清晰的导航目标 | 复用现有路径，不增加另一套设备入口 |
| 首页快捷卡片与 `NetworkConnection` 使用旧 `Network.Device.List`；设备中心使用 v2 Inventory | 设备数量、身份与状态可能不一致 | 首页和完整页共用库存快照与呈现逻辑 |
| 首页设备快捷卡片只显示数量，没有身份摘要 | 用户要先离开首页才能认识设备 | 增加有界设备摘要，保留“查看全部” |
| 大流量图、网口、配置工具、磁盘、共享、Docker、下载与远程域名同时展开 | 高频概览与低频配置混杂 | 缩短流量图，合并同类概况；详细工具进入原有入口 |
| 首页模块显示状态已有服务器持久化设置 | 用户已有偏好需要尊重 | 正式实现添加独立设备摘要模块，保留旧设置迁移与隐藏偏好 |
| 原管理页点击设备打开详情，但没有解析 `route.query.device` | 首页不能直接复用“定位设备”导航 | 正式阶段增加深链读取，并保留列表上下文 |

首页不提供直接断网、改路线、固定地址或一键安装引擎。写入仍在完整管理页完成任务级预览、应用、验证与恢复。
可选能力的缺失提示放在受影响区域，不能把全页变为插件故障面板。

## 交互设计师：三个可比较的方案

在同一路径用 `?variant=A|B|C` 切换。原型重建了 Quickstart 的模块关系，使用现有原创设备图标；示例路由器与设备数据均为合成数据。
导航外壳用于评估布局，不定义新的 LuCI 全局导航；正式实现继续嵌入现有 LuCI 外壳。

| 方案 | 布局与信息优先级 | 取舍 |
| --- | --- | --- |
| A 均衡概览（推荐） | 简短概况在顶；左侧设备摘要和短流量图；右侧常用入口和网络概况；下方 NAS/服务 | 网络和 NAS 混合用户都能迅速找到入口；设备无需等图表加载 |
| B 网络优先 | 流量/连接在前；设备横列位于网络区之后；存储/服务在后 | 网络排障更突出，设备可发现性较弱 |
| C 设备工作台 | 主列设备摘要；侧列系统和常用入口；存储/服务进入主列后段 | 适合设备管理频繁的用户，首页更接近管理工作台 |

推荐 A 的首页设备摘要：

- 桌面和平板最多 **6 台**，手机最多 **3 台**；数量仍按完整快照计算，不能按摘要行数计算。
- 标题显示“在线 N 台 · 本次开机发现 M 台”，强调本机观察范围；不写“全网 M 台”或永久“全部设备”。
- 排序建议先在线，再按最近观察时间；同分使用稳定 deviceId。刷新期间保持现有位置，用户主动刷新或重新进入后再整理排序。
- 名称沿用管理页：用户备注 → 观察到的主机名 → 品牌与类别 → 未命名设备。不用 IP 替代稳定身份。
- 品牌以文字显示，未知类型使用电脑图标。用户手动图标优先，失败回退与管理页相同。
- 每台显示名称、品牌/类型、在线状态；当前地址与连接方式为次级文字。默认收起速率。
- 首页不同时列出路线、限速、时段和额度。进入详情后查看；未来若加入异常标记，只显示一个最高优先级结果，并区分已应用与待验证。
- “显示速率”是可选显示动作；统计不可用显示“暂不可用”，不能填 0。合法的实时零速率与未知值不同。
- 离线和暂停联网是两件事：示例“孩子的平板”在线且因分组时段暂停联网，在详情分别解释。

### 导航契约

“查看全部/更多”进入 `/devicemanagement` 的设备页签，使用全部筛选；点击单设备进入
`/devicemanagement?device=<稳定deviceId>`，打开该设备详情概览，并定位对应设备。
用户可以关闭详情继续浏览列表，也可以从面包屑返回首页。
桌面复用正式详情抽屉，移动复用正式详情全屏；原型用内联详情演示路径和状态，不能当成详情视觉改版。

深链设备消失时，不按旧 IP 打开另一设备。保留列表，提示“该设备当前不在清单中”，提供刷新和返回。
点击设备时保留所选 LAN、筛选与滚动上下文；浏览器后退返回首页，不能触发保存。
`tab` 与 `device` 参数是建议的正式导航扩展；当前生产页尚不支持这些参数。

### 加载与降级

| 状态 | 首页表现 | 保留的动作 |
| --- | --- | --- |
| 正常 / 大量设备 | 完整数量 + 有界摘要；128 台也不渲染无界首页列表 | 查看全部、单设备详情、刷新 |
| 没有设备 | 明确在线 0 / 本次开机发现 0，解释自动发现与观察范围 | 完整管理页添加设备 |
| 首次加载 | 固定高度骨架，数量显示 `—` | 其他模块与导航继续使用 |
| API 首次读取失败 | 设备卡内解释读取失败，数量不显示 0 | 重试、完整页；其他模块不受影响 |
| 刷新失败但有快照 | 保留上次成功数据，显示快照时间与“当前状态待确认” | 重试；不能把旧在线状态当成当前事实 |
| 旧后端 / 不兼容 | 明确缺少兼容接口与三包安装指引；不只显示网络异常 404 | 查看版本/安装说明；其他兼容模块可用 |
| 登录过期 / 权限不足 | 独立提示重新登录或权限原因 | 重新登录；不误报设备离线 |
| 未安装 / 未启用 / 不支持 / 统计异常 | 保留设备列表；仅速率与相关功能暂不可用 | 设备资料、无关功能；完整页能力说明 |
| 本机无 DHCP 分配权 | “本机不负责此局域网的地址分配；固定地址与上网路线请到分配地址的主路由设置。” | 浏览资料和其他可用功能 |
| 分配方不明确 / 错误 | 路线暂为只读，解释先确认分配方 | 查看 LAN 上下文、重试 |

旁路由若确实拥有所选 LAN 的 DHCP 分配权，允许在完整页设置路线；不能按“旁路由”名称一律禁用。
浮动网关只解释 VIP 持有/接管，不能由此推导 DHCP 权限。DNS 继续跟随路线。

### 多端与可访问性

1440px 使用主次两列，1024px 保留 6 台摘要并降低列数，390px 顺序堆叠且只显示 3 台。
列表按钮/链接支持键盘，设计方案用左右方向键切换，输入框与选择框聚焦时不拦截按键。
原型支持明暗主题。正式开发仍需补齐中英文长文案、屏幕阅读标签和真实 LuCI 外壳检查。
设备首页保持一个主要入口“查看全部”；存储/共享/应用模块继续存在，不能因设备管理改版删除 SMART/RAID/NAS 功能。

## 架构师：共享读取与资源预算

以下为**待实现的读取契约**，不宣称当前正式首页已经具备：

1. 抽出一个首页/完整管理页共用的库存 composable/store；按 selected LAN 和 API 版本隔离缓存。
   以 Inventory 的 deviceId 为唯一键，复用 `deviceInventory.ts`、分类、图标解析、名称与 presence 文案。
   当前 `deviceCenterList.vue` 的部分呈现逻辑仍在组件内，应提取后让两处调用。
2. 使用已注册的 `/cgi-bin/luci/istore/lanctrl/v2/devices/`、`network-rules/`、`device-traffic/` 与
   `router-context/`。不可直接从首页调用引擎、TC/eBPF 或 UCI，也不新建另一份全网扫描。
3. 库存页面可见时每 **30 秒**请求一次；路线/能力上下文每 **60 秒**，规则随版本/显式刷新更新。
   首页默认不为每台设备请求策略详情，不做 N+1 查询。显示速率且统计能力可用时才请求 traffic，周期 **5 秒**。
4. 请求完成后再排下一次；每类最多一个请求在途、10 秒超时、并发刷新合并。失败按 30/60/120 秒退避，最多 120 秒。
   可选能力持续不可用时暂停速率请求，恢复只随能力检查或用户重试；离开页面或 document.hidden 时暂停页面采样。
5. 恢复可见先检查缓存时间，再读取一次，禁止后台请求叠加。成功更新与快照过期分别呈现；一分钟未成功刷新标记过期。
   退出或 LAN 改变释放订阅，版本变化清空不兼容缓存。
6. 缓存仅保留最新库存/规则/遥测快照，各最多一个，按后端既有容量上限接收；不累计每次刷新到数组。
   首页趋势最多 60 个样本；历史不进入首页，沿用详情按需加载。有额度策略时既有分钟采样职责保持独立。
7. 网络接口速率来自现有 `Network.Statistics`，不能与设备流量简单求和后宣称为全网总量。
   旁路由只能观察经过本机的流量，ARP/host hints 的观察范围也需尊重所选 LAN。
8. 兼容检查结合服务器版本/接口能力及实际响应：`404 + 不支持 v2` 进入不兼容态；401/403/-1001 进入权限态；
   请求失败进入网络态。单个 404 不足以宣称用户后端一定旧版。HTTP 200 还要检查业务结果。

后端已有 Inventory 与有界 Traffic 模块，本轮无需新统计服务、长期后台任务或修改执行引擎。
未来若 API 不支持显式 selected LAN，必须先在服务读取语义中确认范围，不能仅给前端缓存加 LAN 标签就宣称已支持多 LAN。
