DLSSG Installation Manual

This project lets RTX 20 / 30 graphics cards use DLSS Frame Generation, and on RTX 40 / 50 it uses this project's frame-generation kernels by default; on RTX 30 / 20 you can also turn on this project's INT8 Super Resolution kernels. Follow the steps below one at a time: each step says where to go and what to click.

Read these three first
  1. Only NVIDIA RTX 20 / 30 / 40 / 50 series graphics cards are supported. GTX cards and AMD or Intel graphics cannot use it. Frame generation works only in DirectX 12 games.
  2. Never install it in online games with anti-cheat, such as Delta Force, Naraka: Bladepoint, Marvel Rivals, Call of Duty or GTA V: you risk a ban.
  3. Every time you copy files or change a setting, fully quit the game and start it again for the change to take effect.

Steps

  1. Prepare: turn on Hardware-accelerated GPU scheduling
  2. Unzip the release package
  3. Find the game's EXE folder
  4. Copy the files
  5. Check that it is installed
  6. Use it
  7. How to report a problem

Also: How to edit the settings file · Upgrade · Uninstall · FAQ (including what to do when the game does not load version.dll)

1

Prepare: turn on Hardware-accelerated GPU scheduling

Frame generation needs Windows' Hardware-accelerated GPU scheduling to be on. While it is off, the frame generation option cannot be turned on in any game.

  1. Open the Start menu, type graphics settings and open the result (on Windows 11 the page is called Graphics).
  2. Find Hardware-accelerated GPU scheduling and turn it on. On Windows 11 you first click "Change default graphics settings" (called "Advanced graphics settings" in some versions) to see it.
  3. If you have just turned it on, restart the PC. If it was already on, there is nothing to do.

Two more things:

  • Update the graphics driver to the latest version if you can (in the NVIDIA App or GeForce Experience).
  • If this game has another mod that changes DLSS or frame generation (for example OptiScaler, DLSS Enabler or another version of dlssg-to-fsr3), uninstall it first as that mod's instructions say.
2

Unzip the release package

  1. Right-click the release zip, choose Extract All…, then click "Extract". 7-Zip, WinRAR or Bandizip work too.
  2. Always extract first; do not drag files straight out of the zip.

In the unpacked folder only the 3 items highlighted below go into the game; leave the rest for now:

unpacked folder\
├─ version.dll
├─ dlssg_sm86.ini
├─ dlssg_sm86\              (the whole folder)
├─ alternatives\            only when the game does not load version.dll, see the FAQ
├─ MANUAL.en.html           this installation manual
├─ README.en.md             release notes, opens in Notepad
└─ docs\ and a few others   not needed
3

Find the game's EXE folder

The files go next to the EXE the game actually runs. Many games have only a launcher in their install folder and the real EXE in a deeper folder; in the wrong place nothing happens.

The sure way (works for every game)

  1. Start the game as usual and get to the main menu.
  2. Press Ctrl + Shift + Esc to open Task Manager and go to Details (on Windows 10, click "More details" first if the window is small).
  3. Find the game's process (its name is usually close to the game's, and the one using the most CPU and memory usually is it), right-click it and choose Open file location.
  4. The folder that opens is where the files go. Keep this window open, then fully quit the game.

A few common games

In your Steam library right-click the game → "Manage" → "Browse local files", then go into the folder below:

4

Copy the files

  1. First check whether the game folder already has any of these files: version.dll, winmm.dll, dbghelp.dll, dinput8.dll, dxgi.dll, d3d12.dll.
    • None of them: go on to the next step.
    • Some, and you put them there when you installed this project before: go on to the next step and delete the old ones.
    • Some, and you don't know what they are (most likely another mod): create a folder on the desktop called "game backup" and cut these files into it; put them back when you uninstall this project.
  2. If you installed this project before (any version): first delete the old version.dll, winmm.dll, dbghelp.dll, dinput8.dll, dlssg_sm86.ini and the dlssg_sm86 folder from the game folder (older versions placed four DLLs; now only one is used). If you had changed settings in the old dlssg_sm86.ini, note what you changed and make the same changes in the new one after installing.
  3. Go back to the unpacked folder, hold Ctrl and click these 3 items one after another: version.dll, dlssg_sm86.ini and the dlssg_sm86 folder, then press Ctrl + C.
  4. Switch to the game folder and press Ctrl + V. If Windows asks "Replace or Skip Files", choose Replace the files in the destination.

After copying, the game folder should look like this:

folder with the game's EXE\
├─ (the game's own EXE and other files, leave them alone)
├─ version.dll
├─ dlssg_sm86.ini
└─ dlssg_sm86\
   ├─ backend\
   ├─ kernels\
   ├─ runtime\
   ├─ sr\
   └─ xefg\
Only one DLL at a time

This project gets into the game through this one file, version.dll. That works for the vast majority of games; when a game does not load it, use another one from alternatives instead (see Try another DLL), but never put more than one in the game folder (with several, the log has one proxy_multiple record). The three items also have to stay together: copying only the DLL without the dlssg_sm86 folder leaves frame generation off — on RTX 40 / 50 not even the game's own frame generation runs — and the log has one bundled_runtime_unavailable record.

5

Check that it is installed

  1. RTX 20 / 30: start the game and open its graphics settings. If "DLSS Frame Generation", which used to be grayed out or missing, can now be turned on, it is installed.
  2. RTX 40 / 50 (where frame generation was available anyway), or to be sure:
    1. Following How to edit the settings file, change Level=1 under [Logging] to Level=2 and save.
    2. Start the game, turn on frame generation and play for a minute or two, then fully quit the game.
    3. Open dlssg_sm86\logs in the game folder. Open dlssg_sm86.log in it with Notepad: lines with the game's EXE name (for example Cyberpunk2077.exe) mean it is installed. Every game and every run share this file; new lines are at the end.
An empty logs folder is normal

The factory setting Level=1 writes a log only when something goes wrong, so until you change it to 2, an empty dlssg_sm86\logs, or none at all, is normal. Afterwards you can change it back to 1 or keep 2 (the logs get a bit bigger).

If with Level=2 and frame generation on there is still no line with the game's EXE name in logs\dlssg_sm86.log, it is not installed. First make sure you used the right folder, then follow Try another DLL.

6

Use it

6.1 Frame generation All RTX cards

  1. Turn on DLSS Frame Generation in the game's graphics settings (some games call it DLSS Multi Frame Generation). Pick the multiplier (2X / 3X / 4X) in the game: whatever the game offers can be selected.
  2. The factory limit is 4X. If the game's menu offers 6X or a "dynamic" multi frame generation and you want 6X: following How to edit the settings file, change MaxGeneratedFrames=3 under [FrameGeneration] to 5. If the frame-generation component the game ships supports only 4X, it stays at 4X after this change. The number is told to the game as written; the game's menu can still offer a lower multiplier.
  3. Frame generation needs a high enough base frame rate to look good: if the frame rate with frame generation off is too low, turning it on tends to bring ghosting and broken edges, more visibly the higher the multiplier. Then lower the graphics settings first to raise the base frame rate.
RTX 40 / 50 note

The first time you turn on frame generation the picture freezes for a few seconds while the driver compiles this project's kernels; it does not happen again, except once more after a driver update. This is normal.

On RTX 40 / 50, frame generation on means this project's kernels; there is no setting to switch back to NVIDIA's official kernels (the former AccelerateNewerGpus was removed and does nothing if written). If you do not want it, change Enabled=1 under [General] to 0 and the game uses its own frame generation.

6.2 Super Resolution INT8 RTX 30 / 20 only

It is off from the factory (Mode=Off under [SuperResolution]). On RTX 40 / 50 skip this section: this project does not change super resolution on 40 / 50, and the setting has no effect there.

  1. Following How to edit the settings file, change Mode=Off under [SuperResolution] to one of these four values and save:
    • Mode=M-INT8: preset M on every super-resolution mode, run on this project's INT8 kernels. The usual choice.
    • Mode=L-INT8: preset L on every mode (slower than M at the same mode), on this project's INT8 kernels.
    • Mode=M-FP16 / Mode=L-FP16: the same preset on NVIDIA's own kernels, for comparison only.
    Only Off and these four exist; anything else (the old On included) leaves super resolution off and logs one configuration_invalid.
  2. In the game's graphics settings choose the DLSS Super Resolution mode (some games call it DLSS mode or upscaling mode). Performance and Ultra Performance get faster; Quality, Balanced and DLAA also switch to M / L and are slower than the game's own preset K, so for frame rate do not pick those three.
  3. If the game has DLSS Ray Reconstruction, turn it off: while it is on the game does not use super resolution, and this setting does nothing.

Once it is on, the game's DLSS Super Resolution is replaced with the version in the package (310.9.16). If the game's own version is older, not all of the change in picture and frame rate comes from INT8.

6.3 Other settings Usually left alone

They are all in dlssg_sm86.ini; see How to edit the settings file. For a setting marked "not present", add a line under that section yourself.

SettingSectionFactoryWhen to change it
Optimized[DLSSG]1Frame generation's acceleration level. Factory 1: the picture is exactly the same as with no acceleration at all (bit-identical to the official one); 2 is a little faster (about 1–3 % per generated frame) and no longer bit-identical, with no visible difference side by side; 0 means no acceleration at all. Settings files from older versions have it under [FrameGeneration]; that place is no longer read (a non-default value there such as 1 leaves frame generation off), so use the new settings file.
MaxGeneratedFrames[FrameGeneration]3 (up to 4X)Change to 5 for 6X (see 6.1).
Preset[DLSSG]AWhat is written here runs; the game or driver settings cannot change it. Factory A; an old settings file's Auto runs as A. C = FG Lite: roughly a third to a half less GPU time per generated frame, slightly lower image quality (mostly on the HUD and at object edges). Also runs this project's accelerated kernels, whatever DLSS-G version the game ships. B (UI recomposition forced on) only works when the game provides both a HUD-less image and a UI plane, which most games do not; the log then has one preset_ineffective record.
Engine[FrameGeneration]DLSSXeSS = generate frames with Intel's XeSS-FG model (Intel's model 15, 2X / 3X / 4X). On RTX 30 it is faster than the default DLSS at 1440p and below and about 30 % slower from 4K up (offline GPU time), and it uses about 0.4-0.5 GB more video memory; when the game's back buffer is RGBA16F (some HDR output) frame generation is off, it does not switch to DLSS. See 6.4.
Mode[SuperResolution]OffChange to M-INT8 or L-INT8 on RTX 30 / 20 to use INT8 super resolution (see 6.2).
Level[Logging]1 (errors only)Change to 2 to check the install or to report a problem.
FrameTiming[Logging]not present (off)Add FrameTiming=1 to record what every frame costs (frame interval, GPU time of super resolution and of frame generation); the logs folder gets one plain-text file, frame_timing.txt (one section appended per game launch).

No other setting is in the factory file and they are rarely needed; all of them are described in docs\INSTALL.en.md (opens in Notepad).

6.4 XeSS frame generation (optional) All RTX cards

Following how to edit the settings file, change Engine=DLSS under [FrameGeneration] to Engine=XeSS; nothing else needs changing: XeSS-FG (Intel's model 15) does 2X / 3X / 4X and the factory MaxGeneratedFrames=3 (4X) works as is. Turn on DLSS frame generation in the game as usual and pick the multiplier you want. The [XeSSFG] section has two more settings: FlowResolution (Coarse / Middle / Fine, factory Middle; finer is slower; CoarseAt4K switches to Coarse automatically at 4K output and above) and UseHudless (factory Auto: use the game's HUD-less image when it provides one, otherwise not; 1 requires it always, and a game that does not provide one ends with an error; 0 never uses it). The [DLSSG] settings do nothing under XeSS.

When the game's back buffer is RGBA16F (some HDR output uses it), XeSS refuses frame generation (FG off) with one error-level xefg_feature_refused record; a problem found only while running, such as a missing input XeSS needs, is one error-level xefg_kernel_fatal record naming the cause, and the game then exits. What XeSS cannot run never falls back to DLSS frame generation.

XeSS-FG runs Intel's model 15 as ported by MFG-Unlocker 1.6.0, shipped in the package (inside dlssg_sm86\xefg\xefg_kernels.dll); its 2X is Intel's model 18 graph (bit-identical to the former Model=18), so since 2026-10-26 there is one model and the [XeSSFG] Model line is gone: a line left in an old file is not read. On an RTX 3070 at 4X it is faster than the default DLSS at 1440p and about 30 % slower at 4K (offline GPU time, not frame rate). 46 of its programs are derived from Intel's and fall under Intel's XeSS SDK terms, see THIRD_PARTY_NOTICES.txt.

How to report a problem

  1. Following How to edit the settings file, change Level under [Logging] to 2 (skip this if it already is).
  2. Delete the old files in dlssg_sm86\logs first, then start the game, make the problem happen once and fully quit the game.
  3. Compress the whole dlssg_sm86\logs folder from the game folder: right-click logs → "Compress to ZIP file" (on Windows 10: right-click → "Send to" → "Compressed (zipped) folder").
  4. Submit that zip, together with the text below filled in, wherever you downloaded this project (for example the Issues of its GitHub page).

Where to find the GPU model and driver version

Press Ctrl + Shift + Esc to open Task Manager → "Performance" → the GPU on the left that says NVIDIA. The GPU model is at the top right, and "Driver version" below it is the driver version. A photo or a screenshot of it is fine too.

How to edit the settings file

All settings are in dlssg_sm86.ini in the game folder (editing the copy in the unpacked folder does nothing).

  1. Fully quit the game.
  2. In the game folder right-click dlssg_sm86.ini → "Open with" → "Notepad". On Windows 11 you may have to click "Show more options" first.
  3. Find the section in square brackets, for example [Logging], find the line to change below it and change only the value after the equals sign, for example Level=1 to Level=2. Lines that start with a semicolon ; are explanations; leave them alone.
  4. For a setting you add as a new line (for example FrameTiming=1 under [Logging]): write it on a line of its own below that section's bracket line and before the next bracket line, never inside another section.
  5. Press Ctrl + S to save, close Notepad, then start the game.
If you get something wrong

A value that is written wrong is not replaced by a default: the log records one configuration_invalid and the feature that setting belongs to is not enabled - a wrong frame-generation setting leaves frame generation off (as with Enabled=0), a wrong super-resolution setting leaves super resolution off, a wrong logging or debug setting turns off only that item. Correcting the value fixes it. To go back to the factory settings, copy dlssg_sm86.ini from the unpacked folder over it again.

Upgrade

  1. Fully quit the game.
  2. As in step 4: first delete the old DLL (version.dll, or the one you switched to), dlssg_sm86.ini and the dlssg_sm86 folder from the game folder, then copy the 3 new items.
  3. Make the settings you had changed again in the new dlssg_sm86.ini.
  4. If you are upgrading from 0.3.x you can also delete the folder %LOCALAPPDATA%\DlssgSm86 (type that into File Explorer's address bar and press Enter to open it); the new version no longer uses it.

Uninstall

  1. Fully quit the game.
  2. Delete version.dll (or the DLL you switched to), dlssg_sm86.ini and the dlssg_sm86 folder from the game folder.
  3. If you backed up files in step 4, put them back.
  4. To be extra sure: in your Steam library right-click the game → "Properties" → "Installed Files" → "Verify integrity of game files". It restores game files that were overwritten but does not delete extra files, so item 2 above you always do yourself.

FAQ

The frame generation option is still grayed out

  • Make sure Hardware-accelerated GPU scheduling from step 1 is on and that you restarted the PC.
  • Make sure the files are in the real EXE folder (find it again with Task Manager as in step 3) and that all three items are there.
  • Make sure the game itself supports DLSS Frame Generation and runs on DirectX 12.
  • A value written wrong in the settings file leaves frame generation off (the log has configuration_invalid; see How to edit the settings file).
  • When the frame-generation component the game ships is too old (the generation that can do only 2X, for example The Witcher 3 next-gen), this project does not turn frame generation on (the log has game_runtime_generation).
  • Still no luck: send the logs as in step 7; they show why.

Level is 2, but logs is still empty

  • The most common cause is the wrong folder; find it again as in step 3.
  • If the folder is right, this game does not load version.dll: follow "Try another DLL" below.
  • Antivirus software (Windows Security or a third-party one) may have blocked or deleted version.dll or the other files. This project's DLLs are signed with a self-signed certificate, which some antivirus software flags by mistake. Look in the antivirus quarantine or block history, restore the files and add them as trusted.
  • Windows 11's Smart App Control can also block them while it is on. If that happens, please report it to us; we do not recommend turning it off just for this project.

Try another DLL

The unpacked alternatives folder holds the same program under 5 other names. Try them one at a time in the order below, with only one in the game folder each time:

  1. Fully quit the game and delete version.dll (or the one you tried last) from the game folder.
  2. Copy the next one from alternatives to the game folder, in this order: winmm.dll → dbghelp.dll → dinput8.dll → dxgi.dll → d3d12.dll.
  3. Start the game, turn on frame generation and play for a minute or two, quit, and check whether new lines with the game's EXE name appeared at the end of dlssg_sm86\logs\dlssg_sm86.log (Level has to be 2 first, see step 5). If it did, keep this one; if not, go back to item 1 and try the next.

If none of the five works, report it to us. dxgi.dll and d3d12.dll come last because they sit on the game's rendering path: use them only when the earlier ones fail, and never both at once.

The game does not start or crashes

  • First remove this project's files as in "Uninstall" and make sure the game itself runs normally.
  • If the game itself is fine, install again, change Level to 2, make it crash once, then send the logs as in step 7 and say at which point it crashed.

Generated frames flicker, show corruption or ghosting

  • Check the base frame rate first: if the frame rate with frame generation off is too low, ghosting and broken edges with it on are how frame generation itself behaves; lower the graphics settings to raise the base frame rate and look again.
  • Make sure [DLSSG] says Optimized=1 (the factory value; its picture is exactly the same as with no acceleration at all); if you changed it to 2 or 3, set it back to 1 and try again.
  • If it is still there, report it as in step 7 and say with which settings it appears and with which it does not.

Super resolution is on, but nothing seems to change

  • Only RTX 30 / 20 have this; on RTX 40 / 50 super resolution is not changed.
  • Mode has to be one of M-INT8 / L-INT8 / M-FP16 / L-FP16; any other value (On included) leaves super resolution off.
  • Performance and Ultra Performance get faster; Quality, Balanced and DLAA switch to M / L and get slower than before.
  • Turn off DLSS Ray Reconstruction.

I changed a setting, but nothing seems to change

  • Always fully quit the game after a change. You can check in Task Manager that the game's process is gone before starting it again.
  • Make sure you edited the dlssg_sm86.ini in the game folder, not the copy in the unpacked folder, and saved it with Ctrl + S.

With frame generation on, the controls feel slightly delayed

  • Frame generation makes the picture smoother, but input latency is a little higher than with it off; that is how frame generation works. If the delay clearly gets in the way, lower the multiplier, or report it as in step 7.
