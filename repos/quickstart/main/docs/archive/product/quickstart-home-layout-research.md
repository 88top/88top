# Quickstart 首页自定义布局：参考研究

核验日期：2026-10-15。本文是下一轮布局方案的研究输入，不替换现有产品基线，不表示用户已确认方案。本轮只调查官方资料，不修改 Vue、运行时或真实设备；5180 当前原型尚未因此具备新的行布局能力。

## 1. Home Assistant：分区、卡片尺寸与阅读顺序

官方事实：Sections 以分区组织网格卡片，支持拖动分区和卡片，设置最大分区列数；可开启密集放置填补部分横向空隙，但官方明确指出这会减少对卡片顺序的控制。[Sections 文档](https://www.home-assistant.io/dashboards/sections/)

官方事实：Sections 的卡片布局编辑器可调整占用列数/行数、设为分区全宽及使用更细网格；部分嵌套卡片及 picture elements 不提供相同布局编辑入口。[卡片尺寸文档](https://www.home-assistant.io/dashboards/cards/#resizing-a-card)

官方事实：自定义卡片可通过尺寸接口声明默认值及最小/最大值。2024.11 官方开发说明介绍了分区内十二列网格及 `getGridOptions()`，说明“可调整”仍应受内容尺寸约束。[自定义卡片尺寸说明](https://developers.home-assistant.io/blog/2024/11/06/custom-card-sections-support/)

对 Quickstart 的启发（产品判断）：采用“先组织一行，再调整行内比例”，模块声明最低可读宽度。网络流量与连接在宽屏保留同一组，空间不足才拆行；不默认把后面的系统卡片自动补到前面的洞里。

需要避开的误读：十二列并不等于用户必须理解栅格术语；可以显示 50/50、60/40、67/33 等比例。密集补洞也不等于更好的产品布局，尤其会破坏用户指定的网络→应用→设备顺序。

## 2. Grafana：行分组与自动布局、手动布局的明确分界

官方事实：Grafana 支持把面板分组成行或页签，并允许在分组处选择布局。Custom 可单独调整面板位置与大小；Auto grid 自动安排统一网格，配置最小列宽、最大列数和行高。Auto grid 不允许直接手动缩放某个面板，尝试缩放时会提示编辑自动布局或切换 Custom。[创建仪表盘与布局文档](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard/#panel-layouts)

对 Quickstart 的启发（产品判断）：用户提出的方案更接近“有行分组和尺寸约束的自定义布局”，而非 Grafana 的纯 Auto grid。行内比例由用户控制；容器变化时系统自动换行。两种职责可以共存，但要给出明确约束和确定结果。

需要避开的误读：不能声称 Grafana Auto grid 已实现“任意卡片自由拉宽、其他卡片自动分配剩余宽度”。也不应默认开启填满屏幕高度，否则恰好重新引入首页网络区过高的问题。

## 3. GridStack：可选技术工具，不代替产品规则

官方事实：GridStack 提供移动/缩放控制及布局 `save()`、`load()`；序列化默认可包含卡片 HTML，调用方可以关闭内容保存。布局可按特定列数保存，默认保存逻辑也考虑恢复较宽布局。[GridStack API](https://gridstackjs.com/doc/html/classes/GridStack.html)

官方事实：Responsive 可按断点切换列数；`breakpointForWindow` 默认 false，即按网格容器而非窗口判断。可设列宽目标、最大列数及重新布局模式。[Responsive API](https://gridstackjs.com/doc/html/interfaces/Responsive.html)

官方事实：单卡可声明 `minW/minH/maxW/maxH` 等尺寸约束；网格 `cellHeight: 'auto'` 表示根据列宽计算方格高度，并非根据内容自动等高，内容适配另有 `sizeToContent`。这些名称不能混为同一种“自动”。[卡片选项](https://gridstackjs.com/doc/html/interfaces/GridStackWidget.html)、[网格选项](https://gridstackjs.com/doc/html/interfaces/GridStackOptions.html)

对 Quickstart 的启发（架构判断）：需要拖拽碰撞、跨行自由放置时可评估 GridStack；如果只需要有序行、比例分隔条和断点换行，先使用原生 CSS Grid 与 Vue 状态模型，减少额外布局引擎。当前研究没有做包体积、性能或无障碍实测，不能据此宣布已选型。

需要避开的误读：布局库不会自动规定“网络两卡必须同排且同高”的业务规则。保存也应只保存受校验的模块 ID、行顺序、比例和高度档位，不把 Vue 渲染的 HTML、设备数据或业务权限当作布局持久化。

## 适用于本项目的建议边界（待讨论）

- 以右侧内容容器为宽度基准，扣除系统左侧菜单、内容边距和卡片间距；不修改宿主菜单。
- 宽屏按行编排：网络流量＋网络连接；应用与工具整行；局域网设备＋系统状态；存储及其他模块依次编排。行顺序、组合与比例可编辑，默认提供精调过的预设。
- 同一视觉行统一外框高度；先为行提供紧凑/标准/宽松等高度档位，再由内容布局适配。列表保持有界摘要，详情单独进入；不靠不断扩高卡片显示所有设备和配置。
- 调整比例必须同时满足各模块最小宽度。宽屏可调范围内保持同排；达不到最小宽度时按既定顺序拆为上下布局，不通过挤压文字来满足“必须同排”。屏幕恢复后恢复桌面偏好，不把自动拆行写回用户配置。
- 编辑态才显示拖动和比例把手；同时提供按钮/数值档位，支持键盘和触屏。保存、取消、恢复默认需明确，换行预览要说明触发原因。
- 布局只影响呈现及可见模块读取，不改设备身份、DHCP 权限、应用安装状态及限速语义；不为布局新增后台统计。

以上均为本项目建议，不是三个参考产品共同提供的功能清单。当前尚未完成新的布局 schema、迁移、比例拖动、真实容器断点、跨行等高规则及对应自动化验收；旧原型通过记录不能证明这些新增能力已完成。
