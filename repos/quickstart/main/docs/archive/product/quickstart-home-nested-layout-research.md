# 有序行内三列与纵向堆叠：官方产品研究与设计建议

核验日期：2026-10-15。用户已经选择 R 有序行；本文件研究其行内扩展，不重新开启 R/G/F 选型。仅产品与原型设计，无正式首页、接口或设备改动。资料来自当前官方文档，未实测这些产品的编辑器；文档能力与实现建议分别说明。

## 结论

一行三列、左侧一张与右侧上下两张，都可以保留有序行的心智模型。建议 Quickstart 使用“有序行 → 分栏 → 一张或两张卡片”的有界结构：页面行可以排序，行内先选择布局模板，再配置宽度和卡片。首期提供一列、两列、三列、左大右上下及镜像模板，避免把任意深度的容器树暴露给用户。此为本项目建议，尚非新的产品定案。

## 推荐的 Quickstart 产品规则

以下是根据现有卡片和原型作出的设计判断，需在原型评审确认。

1. 行是主要编辑单元；一行最多三栏。三列适合系统、远程、服务等摘要卡。网络曲线与完整设备摘要的最小宽度较大，不为了三列强行压窄。
2. 每栏放一张卡，或纵向放两张卡。首版编辑 UI 先开放“左大右上下”和镜像，保留其他模板扩展空间。禁止在这个纵向栏中继续横向切分，不出现无限嵌套。
3. 等高要求作用于同一实际水平带的**列外框**。左一张、右两张时：左卡高度 = 右上卡高度 + 栏内间距 + 右下卡高度；不能要求三张卡分别等高。
4. 横向先给 50/50、60/40、三等分等预设，可再拖动分隔线；纵向先给自动分配、1:1 等少量选项。拖动受各卡最小可读尺寸约束。
5. 普通浏览不显示嵌套容器边框。编辑时只强调当前行与当前目标，明确显示“整行移动”“移动卡片”“放入此栏”，键盘和菜单替代拖放。
6. 模板切换应保留卡片和身份；放不下的卡片显式移到后续新行，预览后可撤销。禁止静默删卡或重复出现同一个卡片实例。

## 美观与内容高度必须一起设计

现有 `rowLayout.ts` 中，连接卡最小高度 260px、系统卡 260px、网络曲线 280px。直接把前两张叠在网络曲线旁边，会要求至少 `260 + 18 + 260 = 538px` 的行高，再次导致首屏过大。这个算式是当前原型尺寸的推导，不是建议的最终行高。

因此推荐让支持堆叠的卡片拥有经过设计的“摘要/标准”呈现：摘要保留关键状态与详情入口，详细地址和诊断信息进入详情。原流量曲线继续复用；不能用 CSS 裁切来伪装摘要。先验证约 320–360px 的“曲线 + 两个摘要”示例是否容纳得下，再确定尺寸。不能承诺任意两张现有标准卡都能放成半高。

需要分别验证中文、英文、加载、错误、多设备、多磁盘、缺服务状态。错误提示也应符合高度预算，通过详情呈现长文本；状态语义不得因缩小而丢失。若最小尺寸无法满足，编辑器应提示换模板或增高，不应溢出或隐性截断关键操作。

## 响应式顺序与配置模型

建议保存真实结构，而不是把所有卡片当作平面 x/y 坐标：

```text
页面：有序行列表
行：列比例、行高偏好、有序列列表
列：有序卡片列表（1～2 张）、纵向分配偏好
卡片：稳定实例 ID、模块 ID、呈现模式
```

窄屏按实际右侧内容容器宽度判断。先保持列内组合；空间不足按列顺序换行；手机彻底变成单列。推荐阅读次序固定为“先左栏从上到下，再右栏从上到下”，同时作为 DOM、键盘和屏幕阅读器顺序。例：左 A/B、右 C/D 在手机为 A→B→C→D；若期望 A→C→B→D，应改为两个真实有序行，不能靠视觉补洞和 CSS order 制造另一种顺序。

这一顺序属于 Quickstart 推荐语义，并非上述产品共同承诺。缩窄只改变派生渲染，不覆盖用户宽屏比例、分组和排序；变宽恢复。已换行的列不再强制与上一水平带等高，手机使用各卡推荐高度。

## 成本与下一步原型验收

| 范围 | 交互与实现判断 | 建议 |
|---|---|---|
| 有序行内三列 | 现有比例、最小宽度与顺序换行的扩展；需要第三条宽度约束与拖动命中测试 | 纳入原型 |
| 一侧一张、另一侧上下两张 | 增加栏容器、纵向分配、摘要卡模式、模板转换与响应式顺序验证 | 纳入受限模板原型 |
| 任意深度横纵递归切分 | 需递归最小尺寸传播、多层选中/拖放目标、空容器处理、拆组、撤销和配置迁移；视觉容易碎片化 | 本轮不作为推荐范围 |

建议在 R 预览中提供同内容的“并排三列”“左大右上下”“右大左上下”示例；先体验模板与内容密度，再确定完整编辑器。可测试目标为：无裁切/溢出；真实列外框对齐；中英文与深浅主题可读；缩窄后顺序稳定且不丢卡；变宽还原；键盘操作可达；模板切换可撤销；左侧系统菜单始终不变。这些是下一阶段设计验收输入，尚非本文件已经完成的测试结果。
