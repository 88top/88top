## 产品方案比较

R/G/F/T 是产品选项代号，不对应历史A/B/C原型。R/G/F现有同数据可交互比较，T作为预设理念；不声称实现三套生产布局引擎。下表为结合 Quickstart 的设计判断，不是第三方产品性能实测。

| 方案 | 用户主要操作 | 美观与空间秩序 | 自定义与窄屏 | 实施负担 | 结论 |
|---|---|---|---|---|---|
| R 有序行＋比例卡片 | 分行、跨行拖动、拖比例、行高档位、显隐 | 同排对齐、默认精调、阅读顺序稳定 | 高自由度但受最小尺寸约束；窄屏按顺序拆行 | 中等；需要统一卡片尺寸契约 | 推荐 |
| G 自动等宽网格 | 选择模块、排序、设置列数/密度 | 同类卡片整齐；图表、工具、状态之间容易出现不合适的等宽 | 自动适配简单；难表达网络60/40和应用独占行的个性化组合 | 较低；特殊模块多时例外增加 | 适合以自动整理优先的简单概览 |
| F 自由二维画布 | 自由拖动坐标、横纵缩放、碰撞挤占 | 熟练用户可做复杂布局；普通用户更易产生空洞、错位和过大模块 | 自由度最高；多端恢复和学习成本较高 | 较高；需评估拖拽引擎、序列化、无障碍及响应式策略 | 保留为未来专业模式，不作为默认首页 |
| T 精选模板＋模块开关 | 选择模板、开关少量模块 | 最容易保持设计统一 | 选择简单，比例和分组自由较少 | 低 | 可作为R的预设与恢复入口，不足以单独满足本次目标 |

参考边界：[Home Assistant Sections](https://www.home-assistant.io/dashboards/sections/) 可借鉴分组/拖动及顺序取舍；[Grafana panel layouts](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard/#panel-layouts) 区分Custom和Auto grid，后者不能手动单卡缩放；[GridStack](https://gridstackjs.com/doc/html/interfaces/Responsive.html) 是可选实现工具，其响应式API支持按容器判断断点，并不替代R/F等产品规则。

推荐 R，组合 T 的精选默认模板。正常模式保持简洁，编辑模式才出现行边界、比例和手柄。用户能调整首页，而无需先学习二维画布和碰撞规则。先用 Vue＋CSS Grid 实现行模型；如果原型证明必须支持复杂二维放置，再单独评估库，不先锁定GridStack或新增依赖。

## R的默认提案与约束

- 网络：流量60%＋连接40%，标准同排高度，原面积曲线保留。
- 应用：应用与工具100%，紧凑自动高度，安装更新仍归软件中心。
- 设备：设备约2/3＋系统约1/3，同排等高。
- 存储：磁盘60%＋共享40%，同排摘要，详情单独打开。
- 用户可跨行移动右侧业务卡片、调整顺序和显隐。左侧系统菜单及找回编辑/恢复能力的入口固定。
- 宽度比例针对扣除间距后的内容容器；卡片最小宽高优先于比例偏好。响应式结果不覆盖原布局，变宽后恢复。
- 行高由档位统一管理，不由最长内容无限撑大；拆为单列后卡片可使用自身推荐高度。
- 宽度按5%吸附作为原型起点，提供50/50、60/40、2/3＋1/3等预设和键盘/数值方式；实际最小尺寸与高度档位在M66.7记录，并由M66.8/10校准。
- 加载、失败、空状态、旧后端、缺能力不能伪装成“用户隐藏模块”，不能导致卡片自动消失或改写设备/应用语义。

## M66.7 产品边界、信息与布局规则

目标：先定义本轮要让用户判断什么，避免只讨论拖拽技术。

任务树：用户任务 → 10类卡片信息优先级 → 自定义边界 → 布局/响应式规则 → 方案比较与评审场景。

可测试目标：

1. 流量、连接、应用、设备、系统、磁盘、共享、Docker、下载、远程共10类卡片逐项列出主信息、次信息、入口、加载/空/错误呈现，没有遗漏原功能。
2. 明确系统左侧菜单不变；普通态简洁；编辑态控制比例、分组、顺序、行高、显隐。宽度扣除间距、同排等高、最小尺寸、窄屏拆行与宽屏恢复有可演示的例子。
3. R/G/F比较使用相同数据与内容，T作为预设/恢复方式。列出每种方案要验证的体验，避免只用不同配色充当方案差异。
4. 交付默认布局草图、代表数据及评审操作清单；最小尺寸和高度为可调整的原型参数，正式存储/鉴权/迁移只记录为后续问题。

证据：`docs/archive/evidence/m66/row-layout/07-brief/`，信息清单、布局规则、草图和覆盖表。该阶段自检后自动进入下一步，无需单独人工批准。

## M66.8 多方案高保真视觉原型

目标：让用户在真实Quickstart视觉环境中比较首页结构。

任务树：真实组件/样式复用 → R行比例方案 → G自动网格对照 → F自由布局代表样例 → 同数据深浅/多端截图 → 5180比较入口。

可测试目标：

1. 三方案在同一路由可切换并可分享链接，结构和自由度差异真实可见；相同内容/数据用于比较，不能靠删减模块使某方案显得更整洁。
2. R展示网络60/40等高、应用整行、设备/系统组合；G展示自动等宽与密度；F展示可自由放置的代表结构，标明尚未实现的机制。此阶段不完整开发三个布局引擎。
3. 桌面、平板、手机及深浅主题可查看；标题、字重、留白、图标、颜色、边框保持项目风格。明显溢出/遮挡/低对比须先处理，再交付用户比较。
4. 预览仍由本项目脚本管理5180，确认进程归属，不停止其他项目；合成数据和设计控件与正式入口隔离。

证据：`docs/archive/evidence/m66/row-layout/08-visual-options/`，三方案首屏/整页截图、比较地址、差异说明。此阶段不提前宣称用户已选型。

## M66.9 关键布局交互验证与方案选择【人工确认点一】

目标：用户能亲手体验方案差异，再选定后续深入设计方向。

任务树：R比例/等高小样 → 容器缩放与恢复 → G自动排列控制 → F基础拖动/缩放代表操作 → 对比演示 → 用户选择/混合建议记录。

可测试目标：

1. R网络两卡可用分隔线与比例选项调整，实际同排等高；在代表最小宽度限位后可自动拆行，变宽恢复原偏好。不是静态图片或只有按钮没有结果。
2. G能演示列数/密度改变及自动重排；F能演示基本放置/缩放。未覆盖的碰撞、存储等能力明确标注，不用演示结果承诺完整工程能力。
3. 在实际右侧容器中演示至少一次桌面→窄屏→桌面，卡片不压缩为不可读内容。默认普通态与编辑态都可见。
4. 用户确认采用R、G、F或明确组合，记录选择理由与需修订事项；R仍是推荐，不把“认可方向”自动记成具体候选通过。未收到选择前不开展依赖选型的完整编辑器。

证据：`docs/archive/evidence/m66/row-layout/09-selection/`，操作录像/截图、交互检查、用户决定。只在此处集中等待重要产品决定，不逐阶段重复询问。

## M66.10 选定方案的完整交互原型

目标：把选定方向扩展为首页完整使用与自定义流程。

任务树：全部卡片接入 → 比例/行高 → 跨行与整行排序 → 显隐 → 应用/取消/撤销/恢复 → 首页与详情导航。

可测试目标（按R示例，若用户选择其他方向则先更新同等完整的规则）：

1. 10类卡片可按约定组合、移动或隐藏；比例归一化100%，同排顶部/底部误差不超过1 CSS像素；不丢失或重复卡片。
2. 草稿取消恢复原布局，应用后在本次预览与页面往返保留；撤销、恢复模板和空布局有正确结果，编辑/恢复入口始终可达。刷新恢复示例的行为写清楚。
3. 常用应用、系统工具、软件中心职责清晰；隐藏内容模块后相关入口仍可找到。设备进入同一合成身份详情，其余未实现页面明确为设计占位。
4. 鼠标、键盘和触屏替代操作可用；选中、拖动、限位、落点、成功/失败反馈可体验；对话框焦点和Escape正确，不覆盖系统菜单。
5. 所有修改仅作用于示例数据和布局内存，不安装软件、不写设备策略，也不把内存“应用”显示为已同步真实设备。

证据：`docs/archive/evidence/m66/row-layout/10-interactions/`，操作清单、前后快照、导航与编辑自检结果。

## M66.11 响应式、状态覆盖与视觉自检

目标：形成可供最终人工确认的稳定候选，修正真正的美感和可用性问题。

任务树：实际容器扫宽 → 卡片内容适配 → 多语言/主题 → 异常与大数据 → 浏览器自检 → 人工审图与优化。

可测试目标：

1. 320/390/768/1024/1440/1920px × 中英文 × 深浅共24组基准检查；无横向溢出、控件遮挡或不可读文本。普通态、编辑态及弹层均检查。
2. 在最小宽度临界点前1px/本点/后1px验证；连续缩窄/变宽3次，无振荡、顺序变化或覆盖原布局偏好；按卡片实际尺寸切换内容密度。
3. 合成的大量设备/应用、多磁盘、长名称、空/加载/错误/旧版/权限/缺能力均可切换，保持合理位置与尺寸，不以零值或隐藏卡片冒充失败结果。
4. 原流量图真实绘制和resize正常；页面导航/编辑无控制台异常、非预期请求或真实写操作；不引入重复采样，隐藏/卸载清理仍可验证。仅验证原型浏览器行为，不做路由器资源或实机业务验收。
5. 人工逐项审阅比例、对齐、留白、信息密度、配色、首屏层次和手机操作；自动化通过但视觉仍失衡不得判通过。按既定标准最多优化3次，保留问题和修订前后证据。

证据：`docs/archive/evidence/m66/row-layout/11-review/`，截图矩阵、浏览器报告、视觉问题清单及优化次数。自检通过表示“可供人工验收”，不表示用户已认可美感。

## M66.12 最终人工验收与设计交付【人工确认点二】

目标：用户确认可操作的完整设计；本轮到此完成。

任务树：交付当前5180候选 → 默认首页与编辑演示 → 用户逐项评审 → 反馈修订 → 记录确认 → 设计交付说明。

可测试目标：

1. 用户实际查看默认首屏、整页、编辑态和手机布局，确认比例/等高、应用组织、设备摘要、显隐、排序、换行和恢复。

## M69.1 正式布局与偏好保存

目标：将确认的布局规则实现为正式前端功能，并可靠保存/恢复。

任务树：正式组件设计 → 布局store/schema → 鉴权偏好接口 → 旧模块设置迁移 → 版本冲突/损坏恢复 → 设计代码隔离。

可测试目标：

1. 正式入口独立实现经过确认的规则，不直接发布合成fixtures、评审条、宿主占位和原型操作入口；生产包扫描验证隔离。
2. 保存成功后刷新、重新登录恢复；两个编辑会话冲突有明确提示，不静默覆盖；未登录/越权请求不能读写其他作用域偏好。
3. 旧显隐配置一次迁移，保留回退数据，升级不重置用户选择；损坏/未来版本配置可恢复推荐布局，编辑入口可达，保存失败保留草稿。
4. schema限制模块ID、权重、行数和配置体积；布局不修改DHCP、设备策略、应用安装或执行引擎配置。

依赖：M66.12确认。证据：`docs/archive/evidence/m69/01-layout-preferences/`。

## M69.2 真实数据、应用目录与业务闭环

目标：正式首页使用权威数据，与完整设备页/软件中心共享语义。

任务树：共享库存/能力/cache → 已安装应用目录 → 失败与空区分 → 真实目标与ACL → 生命周期采样 → 版本兼容/降级。

可测试目标：

1. 首页与完整设备页同一身份、数量、在线/联网权限、DHCP权限；深链不以IP作身份，不因拖动或重排生成另一套设备状态。
2. 应用以稳定ID收藏；只展示已验证的目标与适用权限。未安装、服务停止、无入口、无权限、读取失败和空目录各有正确结果；安装成功与服务运行不混同。
3. 修正现有安装目录将读取错误变为空列表的语义，选择一个权威目录来源；内置功能、系统工具、软件中心职责保持一致。
4. 模块共享请求/缓存，无逐卡重复轮询；数据更新不改布局；旧后端、404、登录失效有明确提示且局部降级，其他模块继续工作。

依赖：M69.1及M67相关兼容契约。M68引擎未就绪不阻止验证设备清单及局部降级，但不能据此宣称ARM64数据面通过。证据：`docs/archive/evidence/m69/02-business/`。

## M69.3 当前候选的真实UI与资源验收

目标：对当前源码候选和当前B/C设备验证，不能引用旧原型/旧安装结果。

任务树：只读版本与环境预检 → 登录态多端导航 → 真实API/降级 → 长时间编辑/路由切换 → 资源基线/有界观察 → 清理会话。

可测试目标：

1. 记录源码/前端资源/后端候选标识；先核验B/C的实际服务/API。真实session销毁，不改密码、不用空密码假设替代核验。
2. 桌面/平板/手机真实导航、关键API业务result、控制台/网络、同排等高、显隐/保存/恢复通过；已安装版本与临时候选分别记录，候选模式不证明包元数据一致。
3. 编辑和重排不增加后端服务/采样任务；单通道无重复请求，隐藏/卸载清理；浏览器/后端RSS与请求数先记基线，在预先登记的目标设备预算内做有界观察，不用跑完后的值反定通过线。
4. A仅低频串行只读，无部署/重载/策略写入/故障演练；清理临时文件、进程、会话。24小时观察仍单独延期，不计通过。

依赖：M69.2。证据：`docs/archive/evidence/m69/03-current-acceptance/`。本阶段不替代M70安装包验收。

目标：确认当前正式代码、runtime、配方、feed、安装包和设备实际版本一致。
