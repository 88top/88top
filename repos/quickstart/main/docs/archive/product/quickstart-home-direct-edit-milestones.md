## 产品方案与参考

采用单一编辑方式：普通态保持现有首页；进入“自定义首页”后，在真实卡片上选择、移动、调比例，用附近的小工具调整结构。输入方式不同，布局结果一致。

- Home Assistant Sections支持编辑态直接拖动分区和卡片，借鉴其就地整理方式。[官方说明](https://www.home-assistant.io/dashboards/sections/#rearranging-sections-and-cards)
- Grafana支持拖面板标题移动，用蓝色线条表示目标位置；按所选对象提供对应选项，借鉴明确落点与上下文工具。[官方说明](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard/)
- 拖动还须有无需拖动的点击操作，键盘路径单独覆盖。[W3C Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)

以下交互、尺寸与阶段指标是Quickstart方案，不是第三方产品的规范或性能承诺。

## 交互规则

| 用户任务 | 推荐交互 | 反馈与边界 |
|---|---|---|
| 进入编辑 | 顶部自定义首页，出现紧凑工具条 | 添加模块、撤销、更多、取消、完成；恢复推荐放更多；不再显示常驻大表单 |
| 选择卡片 | 点击编辑手柄或由键盘聚焦 | 高亮选中卡，附近显示移动、隐藏；不只靠hover发现工具 |
| 移动卡片 | 拖手柄，或点击移动后选择目标 | 中心交换、空位移入、行间独占新行；落点显示结果文字与轮廓 |
| 调整整行顺序 | 拖整行手柄至行间，或上/下移动 | 整行结构和内容一起移动，不改变卡片归属 |
| 调整列宽/上下比例 | 拖分隔线，数字实时显示，常用比例吸附 | 点击分隔线也能用比例预设；三列只改变相邻两列，保留合计 |
| 改成三列/上下组合 | 本行工具打开五种结构缩略图 | 已批准的固定深度；镜像保留大卡/堆叠角色；减少槽位时多余卡移到后续新行 |
| 调整行高 | 行工具中的紧凑/标准/宽裕档位及精确值 | 映射现有合法高度；低于当前组合最小高度的选项禁用并说明，不自动裁切或暗改行高 |
| 添加/恢复模块 | 临时模块面板，点模块后选择空位或新行 | 已显示模块标明已添加并可定位；不重复添加，不覆盖已有卡片 |
| 跨屏移动 | 移动到面板列出带结构摘要的目标，选中后确认 | 不要求持续按住跨屏拖动；第一轮不做长页面自动滚屏拖动 |
| 手机整理 | 点击选中→移动→点击目标或目标列表 | 需要结构设置时用底部面板；实际单列不改写桌面模板及比例 |
| 恢复 | 撤销、取消草稿、恢复推荐、完成 | 每个成功手势记一次撤销；预览/无效落点/取消手势不污染历史 |

行和卡片工具一次只展开当前对象的一套。原型场景切换等设计工具继续集中在顶部“设计预览”，不混入最终产品编辑工具。浮层仅在右侧内容区域；手机底部面板可以暂时覆盖内容，关闭后原布局恢复，不占用或修改系统左侧菜单。

动效以占位轮廓、拖动浮层、约150～200ms的轻位移/归位为起点，遵循减少动态效果偏好。使用者松手前能预测结果，动效不代替结果说明。

## 既有规则及实施边界

- 保留行→1～3列→卡片固定层级，五模板和单侧两卡堆叠，不重新进行R/G/F选型。原NetworkFlow图、项目Vue/CSS、设备身份及DHCP分配权语义保持现有基线。
- 逻辑行/列/卡片ID是移动目标的依据。响应式拆出的可视行只用于显示，不得把手机相邻两卡误判为同一逻辑行。
- 有效性使用现有唯一性、模块尺寸和紧凑摘要契约；交换要同时验证两张卡的新位置。当前容器窄而按规则拆行，不等于逻辑模板非法。当前无法显示分隔线时用结构预览和比例选项调整桌面偏好。
- 拖动只预览；确认落点后才提交一个草稿操作。取消、Escape、pointercancel、窗口失焦/卸载、目标变化都要清理；取消手势恢复手势前，取消整个编辑恢复已应用布局。Escape优先退出当前手势/移动模式，再关闭浮层，不静默丢弃整个草稿。
- 布局模型为唯一数据来源。拖动、点击、键盘共用移动和校验命令；优先复用现有Vue与Pointer Events。确有触摸等输入问题时才评估小范围依赖，不新建自由坐标引擎。
- 仍只开发隔离Vue原型，端口5180、合成数据、内存应用，刷新恢复URL示例。真实API、账号偏好、迁移、正式首页接入、SDK/软件包、设备部署不在本计划中。

## M66.13 交互契约与完整场景定义

目标：冻结可预测的移动、选择、取消与响应式规则，避免每种输入各自解释布局。

任务树：当前能力盘点 → 普通/编辑/选中/移动/缩放状态 → 三类落点与整行排序 → 统一命令/校验边界 → 用户任务和测试数据。

可测试验收：

1. 产出状态转换表和动作—结果表，覆盖选择、交换、移入空位、独占新行、整行排序、添加、隐藏、结构、比例、行高、撤销、应用、取消、恢复。
2. 五模板各有结构前后示例；对交换、空位、新行各提供成功与拒绝实例，包含交换后第二张卡不适配、紧凑摘要不支持、行高不足、自身落点、重复模块、无有效目标。
3. 同一任务明确鼠标拖动、纯点击、键盘、手机的操作路径；定义源空位、空行、应用时清理规则，与当前规格一致，不丢失模块。
4. 三次窄屏往返的预期结构、阅读顺序和ID映射有固定数据；所有未决产品语义逐项列出，有重要冲突才集中请求决定。

证据：`docs/archive/evidence/m66/direct-edit/13-contract/`，交互规格、状态表、任务脚本和场景清单。此阶段先通过文档/场景一致性自检，不把规划文档当成可用UI。

## M66.14 就地编辑界面与视觉原型

目标：拿掉大表单，让编辑现场和普通首页同样清晰、美观，建立后续操作承载界面。

任务树：紧凑工具条 → 卡片/行选中与手柄 → 上下文小工具 → 模块/结构面板外观 → 视口与主题自检。

可测试验收：

1. 1440×900默认布局进入编辑后，网络行仍完整出现在首屏，行顶相对普通态下移不超过80 CSS px；无常驻大表单。桌面常驻编辑工具条高度≤64px，手机≤96px（不含系统安全区）。
2. 卡片与行有可发现的选择入口，鼠标、聚焦、触摸选中均能打开对应工具；一次只展开一个对象工具，点击空白可收起。
3. 普通态无编辑边框、手柄、空槽或落点；编辑前后系统菜单边界、原图内容与默认布局规则保持一致。
4. 在320/390/768/1440px、深浅主题下检查工具与浮层：不越出内容边界，不被固定栏裁切；关闭后焦点返回打开者。
5. 已接入操作实际有效；尚未接入的移动/尺寸动作明确禁用或标示，不让视觉样例冒充完整流程。保留同场景普通态/编辑态截图，设计者审阅留白、对比、层级后通过。

证据：`docs/archive/evidence/m66/direct-edit/14-editor/`，首屏位置测量、视觉截图、选择/浮层报告与修订记录。

## M66.15 卡片及整行移动闭环

目标：用户能直接整理首页，落点清楚，拖动、点击和键盘得到一致结果。

任务树：统一移动命令 → 交换/空位/行间落点 → 整行手柄排序 → 跨屏移动到面板 → 取消/撤销/焦点 → 真实操作回归。

可测试验收：

1. 五模板中分别检查允许的交换、空位移入、独占新行及整行排序；目标名称、轮廓和最后结果一致，拒绝原因在确认前可见。
2. 鼠标拖动、纯点击和键盘对同一组任务产生相同的模块归属、顺序和比例。跨屏任务能用目标列表完成，目标有“第几行/哪一列/上下槽位”摘要。
3. 每个成功移动只增加一个撤销步骤，一次撤销精确恢复；自放回原位、无效落点、Escape、pointercancel、失焦和中途卸载不改草稿、不留手势监听器。
4. 全程模块不重复、不丢失，设备ID不变。交换验证两个目标，非法动作不暗改高度或模板；响应式显示行不被写回逻辑配置。
5. 使用浏览器真实输入事件验证路径，不能只调用内部函数证明拖动成功；校验已应用布局在草稿操作期间未改变。

证据：`docs/archive/evidence/m66/direct-edit/15-movement/`，真实输入报告、前后快照、取消/拒绝证据及代表操作录屏或连续截图。

## M66.16 结构、比例与模块管理闭环

目标：全部原有自定义功能通过附近的小工具完成，大表单不再是必经路径。

任务树：五模板轻面板 → 分隔线预览/吸附/比例选项 → 行高档位 → 添加/隐藏/找回 → 完成/取消/撤销/恢复推荐。

可测试验收：

1. 五种模板可在本行切换；减少槽位不丢模块，镜像保留角色，三列及左右堆叠均能真实查看和调整。
2. 列宽、上下比例用指针/点击预设/键盘分别验证；比例合计100%，三列只变相邻两列。成功同排外框对齐误差≤1 CSS px，最小尺寸到达时有明确说明，非法行高不能提交。
3. 行高档位对不同模块显示实际合法尺寸及预览；有精确值入口。不得统一强迫所有模块用同一高度，不重新引入大型常驻参数区。
4. 十类模块均可添加、隐藏、恢复；已显示模块不重复创建，添加到空位或新行可预测，关闭面板取消添加无副作用；隐藏全部后添加、恢复和既有五快捷/八工具入口仍可达。
5. 完成更新本次内存布局，设备详情往返仍保持；取消精确恢复已应用布局；恢复推荐可撤销/取消；刷新仍恢复示例，文案不承诺保存到路由器或账号。完整功能与旧编辑器逐项对照无遗漏。

证据：`docs/archive/evidence/m66/direct-edit/16-layout/`，全功能覆盖表、尺寸/比例测量、模块与草稿恢复报告。

## M66.17 手机、键盘与异常手势适配

目标：输入方式和屏幕变化不妨碍操作，控件边界、恢复和阅读顺序可靠。

任务树：手机点选移动/底部面板 → 手柄触摸边界 → 键盘与焦点/播报 → 宽窄切换 → 中断/大数据/异常场景。

可测试验收：

1. 320/390px不拖动即可完成移动、添加、隐藏、恢复、改模板和取消；结构预览可调整桌面比例，单列实卡不出现误导性的左右分隔线。
2. 在卡片内容上纵向滚动不进入拖动；拖动仅从编辑手柄开始，支持的触摸路径实际验证pointercancel。主要触摸入口命中区≥44×44 CSS px，细分隔线可用更宽透明命中区，命中区不覆盖业务入口。
3. Tab可达全部工具和目标，Enter/Space确认、Escape逐层退出，分隔线有名称、当前值及范围。弹层焦点不丢失、关闭后恢复；移动结果和拒绝原因可被辅助技术读取。记录浏览器与输入方式，不把桌面模拟等同真实手机或完整读屏器认证。
4. 默认、三列、两种堆叠各做三次窄→宽往返，顺序、原比例和源ID保持；编辑中resize、切换数据、目标消失和关闭页面均能清理或恢复，不把半成品提交。
5. 空/全部隐藏、长名称、大量设备/磁盘、失败/旧版/权限/缺服务状态下，选择、移动、工具面板仍可用；旧的320px权限说明问题不能复发。开启减少动态效果偏好后仍有明确静态反馈。

证据：`docs/archive/evidence/m66/direct-edit/17-inputs/`，输入设备与浏览器清单、手机/键盘任务报告、边界/焦点/中断记录。
