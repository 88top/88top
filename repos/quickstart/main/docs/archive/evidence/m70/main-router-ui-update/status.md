# 主路由角色 UI 更新与核验

用户明确要求更新 `root@192.168.30.1`，用于查看另一种路由器角色。本任务沿用 M70 已完成的界面候选，不新增产品设计阶段。

## 目标与任务树

1. 只读预检：固件、运行版本、角色与设置 API、LuCI 注入变量、受保护状态。
2. 更新已冻结的 `9f31d4f` 前端与资源缓存键；先私有备份，不变更后端、软件包、网络配置，不重载或重启服务。
3. 真实短期登录态，串行检查首页、设备、局域网设置的主路由角色内容，以及桌面/手机显示；拦截所有业务写请求，不保存表单。
4. 核对公开资源指纹与配置/进程/路由保护状态，打开截图审查，销毁会话，归档结果。

## 验收标准

- 安装资源与候选逐文件一致，公开主要资源 SHA256 一致。
- 实际 DHCP 权属为本机、路线可编辑时，页面按各能力分别显示，不误报“本页只读”。
- DHCP 配置读取成功时显示真实配置，不能混入旁路由或演示数据。
- 桌面和手机设置页无横向溢出、字段/主操作可见；无 JavaScript 未捕获异常。
- 不提交任何布局、DHCP、路线、限速、分组等变更；允许的 POST 仅限只读 ubus RPC。
- 后端文件、网络/DHCP/防火墙/Quickstart 配置、包数据库、Quickstart PID、默认路由不变。
- 最多三轮检查，失败证据保留，不将 UI 核验表述为后端升级或功能写入验收。

## 已知兼容边界

当前设备为 iStoreOS 24.10.2 / kernel 6.6.93，Quickstart runtime 0.14.0。局域网设备、角色、DHCP、路线接口可用；`home/v1/layout/` 和 `home/v1/launcher/` 返回 404。

此次前端更新使用既有安全降级：临时内置首页，布局及固定项不可保存。没有升级后端，没有宣称首页持久化可用。只读预检 `preflight.json` 已确认本机拥有 DHCP 分配权、路线可编辑，DHCP 配置可读。

- `preflight.py` / `preflight.json`：只读兼容预检及前后保护快照。
- `deploy.py` / `deployment.json`：限定主路由的静态资源更新与校验。
