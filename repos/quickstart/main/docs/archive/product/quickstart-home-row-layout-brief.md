## 布局规则与尺寸起点

R：网络60/40同排320px，应用整行152px，设备/系统65/35同排340px，磁盘/共享60/40同排310px。比例扣除间距18px后计算，最小可读宽度优先；同排高度由行控制。原型尺寸清单位于 `web/src/design/rowLayout.ts`，允许根据实际视觉校准。

两卡最小宽度和加间距大于实际内容宽度时按原顺序拆行；不按整个窗口判断、不跨组补洞。单列允许使用自己的推荐高度。缩窄不写回原分组/比例，变宽恢复。低于单卡建议宽度时使用手机紧凑内容，不强行让页面溢出。

G：默认两列等宽，允许1/2/3列及密度调整，空间不足自动减列。内容与R相同，以呈现轻重不同卡片用等宽网格的体验差别。

F：同样内容，代表性的自由位置组合；编辑时体验基础移动和缩放。窄屏按既定阅读顺序堆叠。明确不提供完整碰撞引擎，不以基础演示承诺生产自由画布能力。

普通态不出现布局边框与分隔线；体验调整后显示对应控制。原型全程标明合成数据，字段/状态遵守既有设备与权限语义。修改只存在本次预览，刷新恢复示例。

## 代表场景与人工评审

三方案使用同样的正常数据、128台设备、空清单、加载、库存错误/旧版/权限、限速服务缺失、网络/存储/服务错误、应用空/加载/错误/大量场景。桌面/平板/手机、深浅、中英文用于后续完整检查。

评审任务：看默认首屏是否平衡 → 调整网络比例 → 查看同排外框 → 缩窄/变宽 → 比较G密度 → 移动/缩放F → 说明偏好及需混合的部分。最终选定一套后补齐跨行、整行排序、取消/撤销/恢复等完整流程。

不把软件中心安装结果、接口权限、真实保存/迁移或真实设备验收作为本轮目标。正式保存作用域与资源预算留作后续设计输入。
