## 已认可的产品模型及架构解释

六组件业务基线：磁盘信息、存储服务、Docker、下载服务、远程域名、系统信息按[原业务核对](quickstart-home-business-widgets-alignment.md)直接复用原组件与表单；统一布局架构不负责重新定义其状态和动作。标准卡有界滚动，摘要打开原完整详情；数据快照、动作宿主与安全目标预览只在当前有序设计入口启用。当前检查见[M66.35～37](../evidence/m66/business-widgets/status.md)。

共享视觉基础：按用户要求，当前有序原型各模块统一采用[原字体与共同字阶](quickstart-home-typography.md)。相同信息角色共享字体规则，标准／摘要保留信息密度差异；字体适配不改变布局偏好、容量、业务状态或读取所有权。当前字体技术证据见[本轮检查](../evidence/m66/home-typography/acceptance.md)。

业务对齐前置：统一展示架构已经实现，不表示原首页各控件的功能均已迁移等价。按用户2026-10-16要求，先核对原业务再升级内部交互；网络连接与网络接口状态各自独立。核对时的原型合并呈现已按M66.32～34拆分，并复用原DNS／软件源表单；实际检查见[执行状态](../evidence/m66/network-widgets/status.md)。字段／动作清单、现存疑点与验收定义见[业务对齐设计](quickstart-home-network-widget-business-alignment.md)。

后续紧凑排版：当前连接标准形态声明最小220px（单卡参考240px），当前接口紧凑形态136px；数值为能力下限，不是强制高度。长值、异常、触屏与标题换行仍参与原自然测量；原完整接口形态、旧版摘要尺寸、布局文档及用户手动空间分配保持。只校准这两种形态的高度声明，不改变自然测量、分配、形态选择与历史算法。[产品规范及当前验收](quickstart-home-network-density.md)。

| 概念 | 负责什么 | 示例 |
|---|---|---|
| 业务模块 | 稳定身份、数据、权限、完整功能入口 | 应用与工具、局域网设备 |
| 展示形态 | 明确信息层级与呈现，不只是缩放 | 完整、标准、摘要；模块可采用更具体名称 |
| 显示属性 | 此形态内可调的有限属性 | 图标目标2／3行、设备展示条数 |
| 槽位 | 行列结构、实际可用宽高、是否上下组合 | 两列的左侧位置 |
| 实际呈现 | 根据偏好与当前容器解析出的结果 | 当前2列×2行图标，窄屏另行适配 |

大／中／小可作为形态缩略图的辅助标签，不作为架构中的唯一语义。摘要可以占较宽槽位，完整形态也不机械等于独占整行。每个模块只登记真正设计并验证过的形态；不要求所有模块凑齐三档。形态变化可以改变内容，但不能改变设备身份、状态、权限或业务含义。

应用的2／3行图标是显示属性；只有卡片内容结构发生实质变化（例如横向启动条与完整启动面板），才登记为不同形态，避免为每个属性组合复制一个形态。

## 应用与工具的具体方案

M66.57当前修订：本节原六项限制为历史记录，由唯一规范R14／R18／R18A替代，当前为默认八工具、最多24收藏、半宽4×2／手机2×4；显式行数与旧收藏仍兼容。稳定入口注册表、目录状态、独立收藏草稿及动作适配分离，布局引擎不保存收藏。完整实施与当前证据见[快捷启动台计划](quickstart-home-launcher-m66-57-62.md)。

候选呈现为“启动条”和“图标网格”。启动条适合较宽较矮区域；图标网格适合与设备等模块并排。两者始终保留“全部应用与工具”入口及同一份常用项，不增加重复软件中心模块。

显示设置提供“图标排布：自动／单行／双行／三行”；这是**目标排布行数**，不只是允许多显示几行。6个常用项选择双行时优先3列×2行，选择三行时优先2列×3行。先按目标行数求建议列数，再结合实际宽度与图标／文字最低可读宽度确定合法列数。条目少时不强行凑足目标行数，例如4个条目在三行偏好下可保持更均衡的2列×2行；面板预览明确显示实际结果。

常用项不足时不复制图标、不填虚假空项、不拉大图标占满空间；空间较窄时限制可见容量并提供“查看全部”。2026-10-19用户决定：标题主操作不附加“还有N个”，中英及所有形态一致，避免挤压标题；完整库仍保留全部入口和正常计数。此决定覆盖历史余量提示规则。首轮6项上限的历史方案已由后续启动台规范更新为最多24个固定项。

计算使用真实标题、内边距、图标区和间距：

`形态所需高度 = 标题区 + 内边距 + 图标行数 × 单行高度 + 行间距`

行数选择影响网格排布与建议高度；公式中的行数使用实际解析结果，不为尚无内容的第三行预留空白。此设置不独占整行，也不自行修改兄弟模块尺寸。普通并排的共同所需高度为各模块所需高度的最大值；上下组合还需按分割比例校验各槽位与间距。例：两行图标的需求若低于设备列表需求，则整行以设备需求为下限；三行图标需求更高，则预览整行增高。具体像素值用原型长名称、手机和明暗主题实测，不把当前300px当作未来所有形态的常量。

网格容量为列数×显示行数。超出部分通过“查看全部”进入现有面板，标题不显示剩余数量；保留常用项顺序，不新增卡片内滚动条或自动轮播。余下的同排空间用于稳定留白与对齐，不无限拉伸图标。

## 统一交互

保留当前真实页面、布局总览和拖动排序。行的“布局”负责结构／比例／行高；模块的操作菜单增加“显示设置”，负责形态和显示属性。两者不各放一份行高设置。普通浏览态不增加常驻设置按钮。

模块显示设置使用现有轻量面板，展示形态缩略预览和此模块的少量属性；支持“自动（推荐）”及用户明确选择。设置中的预览使用子草稿；点击“采用设置”才将属性及必要的行高调整一次写入布局草稿，取消不写历史。预览复用库存和数据快照，不额外启动业务读取。

槽位选择器按结果分为三种，不能将可调整项全部禁用：

| 结果 | 交互 |
|---|---|
| 当前可以放入 | 直接预览来源、目标及被替换模块，沿用既有确认 |
| 调整后可以放入 | 保持可选，显示“调整行高后可放入”或“可改用摘要”；预览具体影响，再一次确认 |
| 没有合法方案 | 禁用并说明具体原因，提供去修改行布局／选择其他位置的路径 |

截图对应流程：在应用的较矮行选择局域网设备 → 看到“当前行较矮，可调整行高后放入” → 预览应用网格与设备并排、共同外框等高 → 点击“放入并调整行高”。已有模块移入时来源留空；被替换模块隐藏；不自动交换或挪走第三个模块。

拖动放入无需额外改变设置时仍然松手提交；若必须改变形态／行高，悬停只预览，松手进入同一个紧凑影响确认，确认前保持原草稿。不能用拖动绕过已验收的显式接受规则，也不增加连续确认弹窗。

每次“移入＋必要属性变化＋共同高度变化”是一个原子动作，一次撤销完整恢复。原有行高足够时保持；减少图标行数不自动收缩整行。隐藏和移动模块保留其显示属性。行结构变化、完成前整理、撤销与取消继续沿用现有规则。

## 架构落点

推荐“模块定义＋显示偏好＋统一适配解析＋现有Vue渲染”，不做外部插件系统，也不把任意样式参数全部开放给用户。

1. **模块定义。** 统一登记稳定模块ID、形态、允许的位置类型、通用／专属属性、最低尺寸、建议尺寸计算与溢出规则。尺寸可依宽度和有限属性计算，不能仅登记一组`minHeight`；不以无界设备／应用总数决定首页高度。
2. **显示偏好。** 保留当前模块ID唯一性；每个模块记录`auto`或指定形态，以及有类型的显示属性。槽位继续只引用模块ID，不把同一模块的大中小注册为三个可重复添加的业务模块。
3. **统一解析。** 一个纯逻辑模块根据定义、偏好、目标槽位与响应式上下文，返回可放入、可调整或不支持，以及明确的变更计划。添加、替换、拖动、改结构、改属性、完成前整理和渲染均复用它，禁止选择器一套门槛、CSS另一套门槛。
4. **渲染。** Vue模块只消费已解析形态、属性和共享数据；形态专用内容可分成小Vue文件，外壳、状态、入口与身份共用。真正变化的应用网格／启动条和设备列表／摘要作为首批实现，避免空泛的全功能配置引擎。

建议解析接口的概念形态：

```ts
resolvePresentation(definition, preference, slotContext)
// → 当前形态、有效属性、最低／建议尺寸、可见容量、适配原因

planPlacement(homeDraft, operation, layoutContext)
// → 直接可用／需要调整／不支持，及明确的 before/after 变更计划
```

二者可封装在同一适配模块，预览和提交消费同一计划，执行前检查草稿版本／目标是否已变化。返回数据，不在解析过程中写草稿或启动请求。

`HomeDraft`从只有rows扩为有版本的`{rows, widgetPreferences}`；属性与行布局共用一个撤销及取消边界。现有常用应用内容清单仍是独立业务设置；改变行数只改变展示容量，不重新排序或删除常用项。未来若在同一布局编辑器内加入常用项内容编辑，需显式纳入同一事务或另行清楚区分，不能共用一个完成按钮却只撤销一半。

数据订阅由现有首页模型持有，形态只作有界投影；切换形态不启动第二套设备发现／流量采样。定义使用有限枚举及类型化选项，持久化数据另行校验版本与字段；从旧rows迁移时补默认偏好，保持既有排序与模块唯一性。

## 自动适配的边界

- 保存用户偏好，实际呈现单独派生；窗口变化不写回布局或偏好。总览缩略卡的88px高度不参与真实尺寸判断。
- 自动形态按模块声明的稳定优先级选择，不能为了显示更多内容不断把行撑大；显式选择的形态在编辑移动时不得悄悄改成摘要。
- 窄屏按既有拆行规则展示，可采用该形态登记的窄屏呈现；变宽恢复原偏好。若确需换形态，编辑器说明当前实际呈现，不暗中覆盖指定值。
- 用户主动修改属性或放入模块导致空间不足时，提供影响预览并一次确认；数据刷新、设备增多和服务状态变化不自动增长行高。
- 同一份计划先验证逻辑结构支持情况，再计算真实页面容器的响应式尺寸，不能因为手机临时拆行就允许宽屏不支持的上下组合。

## 后续原型的可测试目标

1. 应用网格2／3行与设备同排，外框等高；不足空间时给出可操作方案，而不是只有禁用。足够空间和可调空间分别验证。
2. 无修改确认前，布局、属性和历史不变；一次撤销恢复移动、替换、形态、属性及行高全部内容。
3. 常用项少于／超过网格容量、长中英文名、零常用项及应用清单失败均有清楚呈现；全部入口始终可用，容量不改变常用项清单。
4. 不同形态内容实质不同，但设备身份、状态、权限及详情目标一致；缺少限速引擎仍能展示设备数据。
5. 宽屏、平板、320／390px往返保持保存偏好；总览与真实页面使用相同变更计划，不从缩略图尺寸得出结论。
6. 20次形态／属性切换后，跨越完整5秒采样期检查无重复请求／监听；确认、取消、撤销、卸载及原有拖动排序回归。

实施顺序已拆为[M66.26～M66.31](quickstart-home-widget-presentation-milestones.md)：先统一定义和解析规则，再实现应用与设备两种真实模块的显示设置，最后接入槽位协商与完整输入／视觉回归。其他模块登记真实现有形态，未设计的新形态不开放；本文件不计作这些目标已通过。

## 面向真实业务开发的契约

以下是实现建议，字段及文件名可在不改变产品规则的前提下调整。原型与正式业务应尽量共用纯逻辑，而不是把原型的合成读取或内存会话原样投入生产。

### 数据所有权

| 数据 | 所有者 | 形态切换能否修改 |
|---|---|---|
| 行顺序／结构／比例／高度 | 首页布局文档 | 仅经显式操作及计划提交 |
| 模块形态偏好及显示属性 | 首页布局文档，按稳定WidgetId索引 | 仅经显示设置／适配确认 |
| 实际形态／容量／响应式拆行 | 运行时派生结果 | 重新解析，不写回保存偏好 |
| 常用应用清单及顺序 | 现有独立常用项设置 | 不能因容量不足截断或重排 |
| 设备库存／deviceId／状态／权限 | 正式设备业务及共享首页读取 | 只读投影，不能由形态重新推断 |

布局文档建议包含`schemaVersion`、草稿`revision`、`rows`、`widgetPreferences`。`schemaVersion`决定数据结构迁移，`revision`用于防止旧变更计划提交，两者不能混用。正式保存时的服务端版本／并发控制属于独立存储契约，不把本地计数器冒充服务端版本。

首轮每个业务模块仍全页唯一，槽位保存WidgetId引用；隐藏模块的偏好保留在文档内。只保存声明过的有限枚举和有类型的属性，不保存Vue组件名、DOM尺寸快照、实际容量或可执行代码。旧rows迁移补默认值并保持原布局，不在读取时暗中写服务端；非法版本／未知模块或形态给出可恢复诊断，保留原文档副本，不能静默删项。

### 模块定义与变更计划

模块定义至少覆盖：稳定ID、可用形态与响应式策略、每形态真实渲染器、允许位置角色、属性默认值与校验、宽度／高度边界、建议高度计算、内容容量与溢出规则。位置角色包含普通槽位、上下组合的大侧及上下小槽；“支持compact”不能代替位置验证。

解析输入区分逻辑行与当前实际容器：先验证目标结构角色，再按实际内容宽度扣除间距与比例计算空间，随后采用已有响应式规则解析呈现。禁止拿总览88px缩略高度作目标高度。自动推荐规则必须有明确次序，相同输入得到相同结果；宽度临界点实测，避免ResizeObserver反复改写行高形成震荡。

变更计划建议包含：`baseRevision`、来源与目标稳定ID、解析结果、必要变更、被隐藏项、调整原因和候选结果。返回类型区分`ready`、`needs-confirmation`、`blocked`；不以空字符串加多个散落布尔值表达冲突状态。多种合法方案仅展示少量有顺序的候选，不能静默选中改变用户明确形态的方案。

提交前重新检查revision与目标。成功后写入一次完整`{rows, widgetPreferences}`快照并记一步撤销；过期计划拒绝并重新预览。普通数据刷新不应使布局revision失效；影响适配的常用项数量／定义版本改变时，需要校验相应输入版本，避免预览和采用时的容量不一致。

### 原型到正式代码的落点

| 现有位置 | 计划演进 | 正式开发注意事项 |
|---|---|---|
| `rowLayout.ts`、`moduleCapability.ts` | 统一定义登记，兼容旧调用后逐步收敛 | 避免继续复制最低尺寸常量 |
| `orderedLayout.ts`、`slotLayout.ts` | 版本化文档、纯解析与变更计划、完整快照 | 复用同一契约；不为正式页面重写另一套算法 |
| `OrderedHome.vue` | 操作适配器、面板与临时预览 | UI消费计划，不拼装部分状态更新 |
| `HomeApplications.vue` | 声明式形态与图标排布参数 | 常用项清单与显示偏好分别管理 |
| `LayoutPreviewCard.vue`、`CompactPreviewCard.vue` | 按解析结果渲染，同一外壳及数据投影 | 不因换形态新增发现／采样任务 |
| `studioModel.ts`、`fixtures.ts` | 原型共享读取与合成状态 | 正式开发替换为现有请求层和真实库存适配器，不把合成成功响应当实机证据 |
| 正式`web/src/pages/index/`与请求层 | 在设计确认后接入经过测试的契约 | 重新验证登录态、权限、版本兼容、真实导航及API业务 |

不建立外部插件平台、通用页面搭建器或自由CSS编辑器。先以应用网格／启动条和设备标准／摘要这两类真实差异验证架构，再将其余已存在模块接入统一定义；仅存在于表格中的新形态不能自动获得可放入资格。

### 正式开发前需要确定的事项

- 偏好归属与作用域：设备／账号／浏览器、本地还是云端，同一台路由器的多用户是否共享。当前尚未决定；不阻塞内存原型，不得据此假定账号同步。
- 保存与恢复：真实存储接口、ACL、服务端并发版本、结构迁移、损坏配置的备份恢复及失败后的未保存提示；应先检查现有业务能力，再定具体接口，不预造后端路由。
- 兼容边界：旧后端如何明确提示并保留可用功能，前后端支持的偏好schema范围；不能把未知字段或原生404当业务空状态。
- 发布验收：正式源码及前后端版本、runtime与包一致性、匹配架构安装、当前设备API及页面证据另行完成。原型HTTP200或构建成功不替代实机验收；24小时观察仍延期。

这些是未来正式开发的进入条件，不是本轮新增产品功能。需要实际选择时再提交具体方案，不把未决事项隐藏进默认实现。
